# Music Creator Studio YuE2 使い方ガイド

## 1. 必要なもの

- Windows 11、NVIDIA GPU（推奨 VRAM 24GB。INT8 モデルなら 12GB 程度から）、NVIDIA ドライバ 580.88 以上
- 空きディスク 40GB 以上（ComfyUI 約 6GB、YuE2 モデル 8〜12GB、LLM 9GB、分離・整列モデル 2GB ほか）
- インターネット接続（初回セットアップのダウンロード時のみ。以後はオフラインで動作）

## 2. インストールと初回セットアップ

1. インストーラー（`Music Creator Studio YuE2_x.y.z_x64-setup.exe`）を実行します。管理者権限は不要で、`%LOCALAPPDATA%\Music Creator Studio YuE2` に入ります。
2. 起動するとセットアップウィザードが開きます。
   - **環境チェック**: GPU・VRAM・ドライバ・空き容量を確認します。nvidia-smi が 15 秒以内に応答しないとき（ドライバの不調など）は打ち切り、GPU の欄に「GPU 情報を取得できませんでした（nvidia-smi が応答しません。…）」、ドライバの欄に「不明（nvidia-smi が応答しません）」と表示します（先の確認で GPU が見つかっていれば、GPU の欄はその名前と「（再確認では nvidia-smi が応答しませんでした。…）」になり、VRAM もそのまま使います。「再確認」で nvidia-smi がエラーで終わったときも、先に見つかった GPU の名前と VRAM を使い、GPU の欄に「（再確認では nvidia-smi から GPU 情報を取得できませんでした。…）」、ドライバの欄に「不明（nvidia-smi が GPU 情報を返しませんでした）」と表示します）。ドライバか PC を再起動してから「再確認」を押してください（そのまま次へ進むこともできます）。データルートがあってもこのアカウントでは使えないときは、「データルート」の行にその理由を表示し（選択してコピーできます）、ダウンロードの手順でも「ダウンロード開始」の前に同じ理由を表示します。このアカウントでは中を一覧できないデータルートは、空き容量に「不明（データルートにアクセスできません）」と表示し、ダウンロードの手順でも空き容量を表示しません。読み取れても書き込めないデータルート（`C:\Program Files`、読み取り専用の共有、コントロールされたフォルダー アクセスで守られたフォルダなど）は、空き容量と導入済みのものをそのまま表示します。データルートは「保存場所」の後、ダウンロードの手順に入ったとき、ダウンロードが終わったときにも確認し直します（このときは nvidia-smi を使わないのですぐに終わり、空き容量とデータルートの行だけが変わります。GPU とドライバの行は「再確認」でだけ更新されます）。権限を直したら、もう一度「ダウンロード開始」（または「次へ」→「開始」）を押してください。
   - **保存場所**: データルート（ComfyUI やモデルの置き場所。既定 `C:\MCSYuE2`）と、生成した楽曲の保存先（既定 `ミュージック\Music Creator Studio YuE2`）を選びます。
     - データルートは約 80 文字以内にしてください。Windows の長いパスが無効な環境（既定）では、これより長いと pip での導入や ComfyUI の起動に失敗することがあるため警告が出ます。パスに `$` や `%` が含まれる場合も、ComfyUI が環境変数として展開してモデルが見つからなくなることがあるため警告が出ます。
     - 相対パス、ドライブ直下（`D:\` など）、Windows で使えない文字（`< > " | ? *`）、末尾が空白やピリオドのフォルダ名は保存できません。データルートには `;` も使えません（同梱の ffmpeg が見つからなくなるため）。エクスプローラーの「パスのコピー」で付く前後の `"` は自動で取り除きます。
     - ユーザーフォルダそのもの（`ドキュメント`・`ミュージック`・デスクトップ・OneDrive など。ほかのユーザーや Public のものも含みます）を選ぶと、アプリ専用のフォルダ（楽曲の保存先ではサブフォルダ）を勧める注意が出ます（そのままでも使えますが、アンインストール時の自動削除の対象外になります）。
     - 楽曲の保存先を、データルートの中のアプリが管理するフォルダ（`comfy_output\mcs`・`cache\sep_work`・`runtime\ffmpeg` など）やその中にすると、「データルートの中の、アプリが管理するフォルダ（…）そのものです。…」（そのフォルダの中なら「…（…）の中です。…」）という注意が出ます。アプリが作業ファイルを自動で削除するため曲が消えることがあり、アンインストール時もツールとモデルを自動では削除できなくなるので、データルートの外のフォルダを選んでください（設定画面でも同じ注意が出ます）。
     - セットアップがデータルートを Windows のドライブ直下に新しく作るとき（既定の `C:\MCSYuE2` など）は、そのフォルダのアクセス許可をこのアカウント・SYSTEM・Administrators だけにします（ほかの Windows アカウントからは使えません）。別のドライブ（`D:\` や USB ディスク）・ネットワーク上・深い階層のフォルダや、すでにあるフォルダは、上のフォルダの許可をそのまま引き継ぎます。
   - **ライセンス**: YuE2 モデルの重みは CC BY-NC 4.0 ＋個人クリエイター許諾です。個人の創作・収益化は責任ある利用を条件に認められていますが、法人利用には別途ライセンスが必要です。個人クリエイター許諾の対象は YuE2-3B / YuE2-Vae の重みだけです。必須の SheetSage2（カバー / 耳コピ用の転写）と任意の MMS_FA（歌詞の整列）は CC BY-NC 4.0、任意の BS-Roformer（ボーカル分離）は配布元の条件に従います。商用利用の前に各モデルカードを確認してください。
   - **ダウンロード**: 必須（ComfyUI、YuE2 BF16、SheetSage2、ffmpeg、7zr）と任意（INT8 モデル、llama.cpp と Qwen3-14B、分離モデル、アライメントモデル、多言語ローマ字化（uroman））を選んでダウンロードします。
     - 「中断」で止めても、次に「ダウンロード開始」を押すとダウンロード済みの分から再開します（中断はエラーではありません）。pip でのインストールの途中に押した場合は、そのステップが終わってから止まります。ダウンロード・ファイルの確認・展開はすぐに止まり、展開を途中で止めた場合は、次に「ダウンロード開始」を押したときにダウンロード済みのファイルを確認し直してから展開をやり直します（再ダウンロードはしません）。
     - 開始前に、データルートのドライブの空き容量が足りるかを確認します（展開後のサイズを含む概算に、ダウンロードがあるときは 1GB の余裕を加えます。途中まで取得済みのファイルの分は差し引き、pip で入れる項目は多言語ローマ字化を約 64MB、audio-separator を約 1GB として数えます）。足りないときはダウンロードを始めずに知らせます。
     - ダウンロードしたファイルは SHA256 を確認してから本来の名前になります。確認の途中でアプリを閉じても、次回もう一度確認します。途中まで取得したファイル（`.part`）は、同じファイルなら続きから再開し、別のファイルのもの（古い版が残したものなど）は捨てて最初から取り直します。
     - 「ダウンロード開始」「中断」は、ダブルクリックの 2 回目を無視します。
     - セットアップの実行中に画面を再読み込み（F5）しても、セットアップは続きます（「画面を再読み込みする前に始めたセットアップが続いています。…」と表示して進み具合を表示し、「中断」で止められます）。実行中は保存先（データルートと楽曲の保存先）を変更できません。再読み込みの後などに「開始」や「アプリに戻る」を押したときにまだ実行中なら、その進み具合を表示するので、終わってからもう一度「開始」を押してください。
     - 楽曲の保存先がまだ作れない場合（外付けドライブを外しているなど）でもセットアップは完了できます。保存先のフォルダは、曲を生成するときに作ります。データルートやその中のフォルダを作れないときは、エラーにそのフォルダのパスを表示します（ほかのアカウントのデータルートを使おうとしたときは 12 章）。
     - 任意コンポーネントの失敗では止まらず、ほかのコンポーネントの導入を続けます（失敗した項目は最後にまとめて表示します。チェックを外すと次へ進めます）。
3. 「開始」を押すとメイン画面になります。初回セットアップと、設定画面でモデル精度を変えて保存したことがない場合のやり直しでは、VRAM が 20GB 未満で INT8 モデルを導入済みなら INT8 が自動で選ばれます。

アプリは 1 つだけ起動できます。もう一度起動すると、開いているウィンドウが前面に出ます（開発版とインストール版も同時には起動できません）。起動中のアプリが管理者として実行されている場合などは、「Music Creator Studio YuE2 は既に起動しています（管理者として実行中の可能性があります）。…」と表示して、新しく起動した方は終了します（待機中や生成中の曲には影響しません）。ウィンドウは画面の作業領域に収まる大きさで開きます（高さは 600px まで縮められます）。

セットアップは「設定 → セットアップをやり直す」でいつでも表示でき（確認のあと、すぐにウィザードが開きます）、後から任意コンポーネントを追加できます。生成・ツール（転写・分離・整列・譜面の計画）の実行中や待機中の曲があるとき、ComfyUI の待ち行列に処理があるときは押せません（ボタンを押した時点と確認のあとにも確かめます）。
- 設定画面で変更したデータルートと楽曲の保存先は、ウィザードの「保存場所」の手順に入力された状態で開きます。そこで「次へ」を押すまでは保存されません。ほかの未保存の変更は破棄されます。
- 作曲・カバー / 耳コピ・AI 編集・ボーカル分離・書き出しの各画面で入力中の内容もリセットされます（確認画面にも表示されます）。
- やり直しでは、必須コンポーネントがすべて導入済みなら、大きな任意コンポーネント（INT8 モデル・llama.cpp・Qwen3-14B）は最初から選ばれていません。追加したいものだけにチェックを入れてください。必須コンポーネントが足りないとき（新しいデータルートにセットアップするときなど）は、初回と同じく INT8 モデル・llama.cpp・CUDA ランタイム・Qwen3-14B も選ばれた状態で始まるので、使わないもののチェックは外してください。
- 何もダウンロードせずに戻るときは、各手順の「アプリに戻る」を押します（ウィザードを開く前の保存場所に戻ります）。このボタンは、ウィザードを開いた時点で必須コンポーネントがすべて導入済みのときに表示されます。
- 生成やツールの実行中は、やり直しのボタンは使えません（ウィザードの表示中は生成の進行状況やキャンセルボタンが見えなくなるため）。
- 設定画面でモデル精度を変えて保存したことがあれば、その精度のチェックポイントが未導入の場合を除き、精度は変わりません（保存したことがなければ、初回と同じく VRAM が 20GB 未満で INT8 モデルを導入済みなら INT8 に切り替えます。それ以外は今の精度のままです。「アプリに戻る」でも同じです）。

## 3. 画面の基本

- **ヘルプ**: 各画面の見出しの右にある「？ ヘルプ」（または F1 キー）で、その画面の説明・基本の流れ・各項目の意味（範囲と既定値）を表示します。設定のヘルプには、アプリの概要・前提条件・制限事項・トラブルシューティング・インストールとアンインストールもあります。
  - 左の目次から節へ移動でき、「画面」の一覧でほかの画面のヘルプも読めます（アプリの画面は切り替わりません）。
  - 上部の検索欄に言葉を入れると、一致する項目だけを表示し、一致した箇所を強調します（大文字・小文字、全角・半角、カタカナ・ひらがなは区別しません。空白で区切った言葉は、すべてを含む項目を探します）。この画面のヘルプに見つからないときは、見つかったほかの画面のヘルプと件数を示します。日本語入力の変換中は、確定してから検索します。
  - Esc・「閉じる」・ヘルプの外側をクリックすると閉じ、開く前の場所（ボタンや入力欄）に戻ります。ヘルプを開いている間に確認（AI の作成が終わったときの確認、終了の確認など）が出たときは、確認が手前に表示されます。確認ダイアログやヘルプが開いている間は F1 は働きません。
  - 入力欄で F1 を押すと、その欄からフォーカスが外れるため、曲名の変更や時刻の欄などはその時点で確定します（ヘルプボタンを押したときと同じです）。
- **画面を切り替えても入力は残ります**: 作曲・カバー / 耳コピ・AI 編集・ボーカル分離・書き出しの 5 画面は、一度開くと別の画面に移っても内容を保ちます（歌詞・スタイル・譜面とピアノロールの編集、転写した譜面とその編集、AI 編集の対話、分離結果、書き出しのタイミングとメタデータなど）。別の画面にいる間に終わった処理（転写・分離・タイミングの自動検出・AI の下書きや返答・譜面の計画）の結果もその画面に入ります。戻ると、離れたときのスクロール位置から表示します。ライブラリと設定は開くたびに作り直します。アプリを終了したときと「セットアップをやり直す」のあとは、入力は残りません。
- **表示していない画面**: 音を出しません（プレイヤーや譜面の試聴は画面を切り替えると止まります）。確認が必要になったとき（AI の下書きや譜面の計画が終わったときなど）は、その画面を開いたときに確認を表示し、「「<画面>」画面で確認が必要です（…）。画面を開くと表示します」とお知らせします。確認を表示するまで、サイドバーのその画面の名前には「確認待ち」の印が付きます（お知らせがほかのお知らせに隠れても消えません）。表示していない画面は、ライブラリの選択を変えません（作曲で待ち行列に追加した曲は、完了のお知らせから開けます）。表示していない画面からの完了のお知らせには画面名が付きます（例: 「転写が完了しました（「カバー / 耳コピ」画面）」「AI の返答が届きました（「AI 編集」画面）」）。
- **お知らせ**: 画面下のお知らせは約 6 秒、エラーは約 15 秒で消えます。生成の失敗、確認待ちのお知らせ、起動時に設定ファイルを読み込めなかったお知らせは × で閉じるまで残り、その上に別のお知らせが出ても、そのお知らせが消えると元に戻ります。お知らせの文字は選択してコピーできます。
- **進行状況**: 生成中の曲の段階（「準備中」「AI の応答を待っています」「ComfyUI を起動中」「ABC 譜面を計画中」「音楽トークンを生成中」など）と、待機中の曲の一覧を表示します。生成中の曲と待機中の曲は 1 曲ずつ「キャンセル」でき、「待機中をすべてキャンセル」は確認のあとで待機中の曲だけを取り消します（生成中の曲はそのまま続きます）。待機中や「ComfyUI を起動中」の曲のキャンセルはすぐに反映されます（ComfyUI の起動は裏で続きます）。生成中の曲がないときは、最後の曲の結果（「完了」「エラー」「キャンセル済み」）を次の生成が始まるまで表示します（起動してからまだ生成していなければ「実行中の生成はありません」）。ログには曲ごとに「── 「曲名」 ──」の区切りが入り、最新の行まで自動でスクロールします（上にスクロールして読んでいる間は動きません）。
  - 待ち行列を出た曲はすぐに「準備中」になり、ライブラリでも「生成中」になります。生成中の曲は削除できず、「待機中をすべてキャンセル」の対象にもなりません（1 曲ずつ「キャンセル」できます）。確認の間に生成が始まった曲は、取り消さずにそのまま続けます（お知らせは出ません）。取り消しの処理中に始まった曲があったときだけ、「N 曲をキャンセルできませんでした（すでに開始または終了した可能性があります）」と表示します。
- **二度押しの防止**: 生成ボタンを押した直後（1 秒以内）の同じボタンの二度押しは無視します。その後に続けて押せば、さらに曲を待ち行列に追加できます。
- **処理中は競合する操作を止めます**: 画面が自分の処理（AI の作成、譜面の計画、転写、分離、タイミングの自動検出、書き出し、AI 編集の応答待ち、生成の送信中の確認、歌詞のひらがな化）を行っている間は、その処理と食い違う操作のボタンが押せなくなり、理由がツールチップに表示されます（例: 作曲で「歌詞とスタイルを作成」中は「生成する」「インストゥルメンタル版を生成」「ひらがな化」「リセット」「選択中の曲の設定を再利用」とピアノロールの再生成、カバーで転写中は音源の変更と生成、ボーカル分離中は音源とモデルの変更、自動検出中は打刻・時刻の入力・行の作り直し・言語と音源の変更、AI 編集の応答待ち中は「この譜面で再生成」「選択中の曲を読み込む」「LLM を停止（VRAM 解放）」/「LLM を起動」、作曲・カバー・AI 編集で歌詞をひらがな化している間（「ひらがな版を破棄」の前の確認を含む）は生成のボタンとピアノロールの再生成）。文字の入力は止めません（作成中に書き換えた歌詞やスタイルは、AI の案で置き換える前に確認します）。別の画面への切り替えは常にできます（処理は画面の裏で続き、結果と確認はその画面に残ります）。
- **音声ツールのキャンセル**: 転写（カバー / 耳コピ）、ボーカル分離、タイミングの自動検出（分離と歌詞の整列。書き出し）、譜面の計画（作曲の「インストゥルメンタル版を生成」）の実行中は、実行ボタンの横に「キャンセル」が出ます。ComfyUI が処理を受け付けるまでは押せません（「ComfyUI が処理を受け付けるとキャンセルできます」）。ボーカル分離の「出力を保存中」の段階ではキャンセルできません。キャンセルした処理はエラーではなく「キャンセルしました」と表示します。ボタンと進行状況・エラーは、その処理を始めた画面にだけ表示します（書き出しのタイミング自動検出のための分離は、ボーカル分離の画面には表示されません。その逆も同じです。作曲・カバー・AI 編集の画面の進行状況とログに出るのは、曲の生成だけです）。
- **AI への依頼のキャンセル**: 作曲の「歌詞とスタイルを作成」と AI 編集の送信は、応答を待つ間「キャンセル」で取り消せます（ローカル LLM は起動中でもそのまま動き続け、次の依頼に使われます。クラウドの API では、送信済みの依頼が課金されることがあります）。キャンセルはエラーではなく「キャンセルしました」と表示します。画面を再読み込み（F5）したときも、応答待ちの依頼とローカル LLM の起動の待機は取り消されます（起動中のローカル LLM はそのまま起動を続け、すぐに停止もできます）。
- **確認ダイアログ**: 確認が重なったときは、新しいものが手前に表示され、キーボード操作もそれに対して働きます。ボタンのダブルクリックの 2 回目で、確認が閉じたり答えが選ばれたりすることはありません。
- **終了するとき**: 生成（待機中の曲を含む）・音声の処理・書き出し・セットアップの実行中にウィンドウを閉じると確認が出ます。確認には生成中の曲名、待機中の曲の数、音声の処理（転写・分離・歌詞の整列・譜面の計画）と書き出しの件数が表示され、終了すると待機中の曲も生成されません。書き出し中に終了すると、保存先に作業用のファイル（`*.mcs-tmp.*`）が残ることがあります（次に同じ名前へ書き出すと自動で削除されます。手動で削除してもかまいません）。10 秒以内にもう一度ウィンドウを閉じると、確認せずに終了します（実行中の処理は中断されます）。
- **スリープの抑止**: 生成（待機中の曲があるときを含む）・音声の処理・書き出し・セットアップの間は、Windows が自動でスリープしないようにします（画面の消灯は妨げません）。手動でスリープしたときやノート PC のふたを閉じたときは止まりますが、スリープしていた時間は処理の制限時間（12 章）に数えず、復帰後はそのまま続きます。
- キーボードでは、作曲の「最近の生成」の行や書き出しの歌詞の行に Tab で移り、Enter / Space で選べます。

### 3.1 用語

| 用語 | 意味 |
|---|---|
| 生成 | YuE2 で音声を作ること（「生成する」「この譜面でカバーを生成」） |
| この譜面で再生成 | 譜面を固定して音声だけを作り直すこと（作曲のピアノロールと AI 編集）。（Full）/（Melody）は使うモード。譜面のない曲の AI 編集では「再生成（譜面なし・Off）」「再生成（譜面を再計画・Melody / Full）」 |
| 譜面の計画 | YuE2 が ABC 譜面を作ること（進行状況では「ABC 譜面を計画中」） |
| 作成 | AI による歌詞とスタイルの下書き（「歌詞とスタイルを作成」） |
| 作り直す | 元の内容から作り直すこと（「歌詞から行を作り直す」「チップの内容で作り直す」「行を作り直す（書き出しは中止）」） |
| インストゥルメンタル版 | 歌なしの曲（「インストゥルメンタル版を生成」「インストゥルメンタル版カバー」）。ライブラリの曲名では短く「（インスト）」「インスト: …」と付きます |
| 伴奏声部 | 譜面の 2 声部のうちボーカル以外（`V: Ins`）。「伴奏」だけのときは分離した伴奏の音声を指します |
| 転写 | 音源を譜面にすること（カバー / 耳コピ） |
| タイミングの自動検出 | 同期歌詞の時刻を自動で入れること。分離と歌詞の整列の 2 段階 |
| 読み込み / 書き出し | ファイルやデータを取り込む / 保存すること |
| キャンセル / キャンセル済み | 処理や生成を取り消す操作 / 取り消された曲の状態 |
| 待機中 | 生成の順番を待っている状態 |
| 中断 | 実行中の処理が途中で止まること。セットアップのダウンロードの中断（「中断」ボタン、通信の途切れ）は次の「ダウンロード開始」で再開できます。ComfyUI 側からの割り込みやアプリの終了で止まった生成・音声の処理は再開できません（曲はエラー「アプリ終了により中断」などになるので、もう一度生成します） |
| 中止 | 処理を始めずに、または途中で取りやめること（確認に答えられなかった、曲が削除された、書き出しの確認で「行を作り直す」を選んだ など） |

## 4. 作曲

0. **AI で歌詞とスタイルを作成（任意）**（作成中は横の「キャンセル」で取り消せます）: 作曲画面の一番上の欄に、曲のイメージを日本語で書いて「歌詞とスタイルを作成」を押すと、AI（既定はローカル llama.cpp）がセクションタグ付きの歌詞、英語のスタイルプロンプト、スタイルのチップ選択をまとめて入力します。長さは「短め 約1分」「標準 約3分」「長め 約4分」から選べ（セクションの数と行数で長さが決まるため、AI には長さに合った構成を守るよう指示します）、歌詞の言語は「歌詞の言語」の設定に従います（スタイルの言語のチップもその言語になります。「その他」では、AI が選んだ言語のチップがスタイルの先頭に書かれた言語と一致するとき（韓国語など）だけそのチップを残します）。AI は常に歌のある曲を書きます（歌なしにしたいときは 4.2 の「インストゥルメンタル版を生成」を使ってください）。作成後は自由に手直しでき、日本語ならそのまま「ひらがな化」に進めます。ローカル LLM の思考モードでは、思考を約 1,000 トークンで切り上げて歌詞を書かせるため、1 回 30〜60 秒ほどかかります（8 章）。ローカル LLM の応答が長さ上限で途切れたとき（同じ語を繰り返し続けたときなど）は、「AI の応答が長さ上限で途切れたため、思考なしでもう一度作成しています」と表示して自動でもう一度作成します（さらに 1 分ほどかかることがあります。成功すると「2 回目の作成で成功」と表示）。2 回とも途切れたときだけ「LLM の応答が 2 回とも長さ上限で途切れました」になります。
   - 入力済みの歌詞（ひらがな版を含む）や手で書いたスタイルがあるときは、置き換える前に「置き換える」「スタイルだけ反映（歌詞と曲タイトルはそのまま）」「キャンセル」を選ぶ確認が出ます（入力した曲タイトルも置き換えの対象です）。歌詞とスタイルが前回の AI の案のままなら確認しません。作成中に歌詞やスタイルを編集した場合も、置き換える前に確認します。
   - **曲タイトル**: 歌詞欄の上の「曲タイトル」に入力した名前が、生成する曲（バリエーションも同じ名前）の曲名になります。AI の作成では案のタイトルがここに入り、自由に書き換えられます。空欄のままなら自動で付けます（この章の最後の「曲名」）。「インストゥルメンタル版を生成」は入力したタイトルに「（インスト）」を付けます。「選択中の曲の設定を再利用」はその曲の名前も入れます。生成後の名前はライブラリで変えられます（10 章）。
     - 1 行・60 文字まで（文字数は Unicode のコードポイントで数えます。多くの絵文字は 1 文字ですが、肌の色付き・国旗・ZWJ でつないだ絵文字は 2 文字以上になります。欄の右に文字数を表示します）です。上限を超える入力・貼り付け・変換の確定では、入力した文字の後ろの部分が入らず、すでにあるタイトルは消えません。AI の案や再利用した曲の名前が 60 文字を超えるときは 60 文字で切り、改行は空白にします。
   - 「歌詞とスタイルをリセット」は、確認のあとで歌詞（ひらがな版を含む）・曲タイトル・スタイル（チップとプロンプト）を空にします。
1. **歌詞**: `[Verse]` `[Chorus]` などのタグでセクションを区切ります。日本語ボーカルは実験的対応です（公式ベンチマークは英語・中国語のみ。ComfyUI 公式ドキュメントでは日本語も対応言語に含まれます）。
   - タグは YuE2 に決まった語彙があるわけではなく、`[ ]` の行は曲構成のヒントとしてそのままモデルに渡されます（英語推奨）。よく使う 7 種類（イントロ / Aメロ / Bメロ / サビ / Cメロ / 間奏 / アウトロ）はボタン、それ以外は「その他のタグを選んで挿入…」のリスト（フック、ラストのサビ、インストゥルメンタル、ギターソロ、ラップ、語り、ささやき、ハミング、男女の歌い分け、フェードアウトなど、公式サンプルで使われているもの）から選べます。
   - リストにないタグは「任意のタグ」欄に書いて「[ ] で挿入」（または Enter）で入れられます（60 文字まで。絵文字も 60 文字分入力でき、長いタグは挿入するときに 60 コードポイントで切ります。60 文字を超えて入力すると、欄の下に「タグは 60 文字までのため、最後の N 文字は挿入されません」と表示します。サロゲートペアは分けませんが、国旗や ZWJ でつないだ絵文字は途中で切れることがあります）。使ったタグは「最近使ったタグ」に残ります。
   - 「番号を付ける」を ON にすると、Aメロ・Bメロ・サビなどが `[Verse 1]` `[Verse 2]` のように通し番号付きで挿入されます（公式サンプルで多い書き方です）。
   - タグは歌詞欄のカーソル位置に 1 行として挿入されます。カーソルが行の途中にあるときはその行の前、行頭や行末にあるときはその位置に入ります（歌詞欄を一度もクリックしていなければ末尾）。
   - 歌詞が空（またはタグだけ）のまま「生成する」を押すと、歌詞なしで生成します。歌なしになるとは限らないので、歌なしの曲は「インストゥルメンタル版を生成」で作ってください（YuE2 の性質上、それでもまれに声が混じることがあります。対処は 4.2 の最後の項目）。
2. **スタイル**: 日本語のチップ（言語・ジャンル・ボーカル・声質・楽器・雰囲気・テンポ）を選ぶと英語プロンプトが組み立てられます。直接編集もできます。プロンプトを手や AI で書き換えたあとにチップを押しても、プロンプト全体は置き換わらず、そのチップの語（カンマ区切りの 1 項目）だけを追加・削除します（例: 「ピアノ」を外しても `Rhodes piano` は残ります）。言語とボーカルは 1 つだけ選べる項目で、選ぶとプロンプトにある別の言語・ボーカルの語を置き換えます（例: 既定の `Japanese, ...` で「英語」を押すと `English, ...`、`bright female vocal` で「男性ボーカル」を押すと `bright male vocal`）。
   - テンポのスライダーは、常にプロンプトに書かれているテンポを表示します（40〜220 BPM。範囲外のテンポは表示だけ実際の値で、つまみは端に置きます）。`60-70 BPM` や `〜`・`～`・`—` を使った範囲も読み取ります。左端は「指定なし」で、プロンプトのテンポの項目（範囲を含む）を取り除きます。テンポの項目は `NN BPM` に書き換え、`upbeat 120 BPM groove` のように文中にあるテンポはその場で書き換えます。文中のテンポしかない場合は「指定なし」の端がないので、消すときはプロンプトを直接編集してください。
   - テンポは `NN BPM` のほか、`BPM 140`・`BPM:140`・`BPM140`、`BPMは140`・`BPMが140`・`BPM約140`・`BPM≒140`・`BPM: ~140`・`BPM (140)`・`BPM ‐ 140`、`140 beats per minute`（`140 beats-per-minute`）、全角の `１４０ ＢＰＭ`、「テンポはBPM120」「女性ボーカルBPM128」のように日本語に続けた書き方も読み取ります（`NN BPM` と `BPM NN` の両方があるときは `NN BPM` を使います）。`BPMを140くらいに`・`BPMも140`・`BPMで140`、`BPMはおよそ140`・`BPM around 140`、`BPM【140】` も読み取ります。
     - `BPM` の後の数は 10〜299 だけをテンポとみなします。`BPM 808` のようなドラムマシン名、`BPM 90s`・`BPM 90年代` のような年代、`low-BPM 120` のようにハイフンで英単語につながった（修飾語の）BPM の後の数、`BPM 140ish` のように英字が付いた数はテンポとして扱いません。
     - 40 未満の数の後に語が続くとき（`高BPM 16ビート`・`medium BPM 32 bars`）は、その語を数えた数としてテンポとして扱いません（`BPM 30` のように項目の最後なら 30 BPM）。
     - `BPMが10%アップ` のような割合や、`BPMを50上げて`・`BPM 50くらい下げる` のように 100 未満の数の後に増減を表す語（上げる・下げる・落とす・速く・遅く・増やす・増す・アップ・ダウン など。ひらがなや「引き上げる」、丁寧形（上げます・上げません・上げなさい）・意志形（上げよう）・命令形（上げろ・上げよ・加速せよ）も含みます。スペースや読点の後に続く、命令形と同じ字で始まる別の形（`BPM 90 上がれるサビ`・`BPM 70 落とせない想い`・`BPMが90、引けを取らない`）は次のタグとみなして 90・70・90 と読みます（`BPM90上がれるサビ` のように数に続けた書き方や、「を・が・も」の後に読点なしで続く場合の多くは、変化の量とみなして読みません）。`BPMを50高く`・`BPMが50加速`・`BPMが50↑` のように「を・が・も」の後では、高く・低く・速めに・加速・上昇・↑↓ なども含みます）が続くときは、変化の量としてテンポとして扱いません（`BPMを80に落として` のような変更後のテンポや、100 以上の数は読みます。`BPM 50 - 60 上げて` のような変化の量の範囲は、範囲の最初の数も読みません。後ろの数が小さい「BPM NN - NN」は範囲ではありません。項目の終わりにあれば（`trap, BPM 140 - 70`・`BPM174-87`）最初の数を読み、書き換えるときは丸ごと置き換えます。後ろに語が続くとき（`EDM, BPM 128 - 64 bars intro`）は最初の数（128）だけを読んで置き換え、`BPM 140-70 half-time` のように最初の数だけでは読めない書き方は読みません。改行は読点と同じく項目の区切りで、行をまたいで範囲や `NN BPM` とはみなしません。↑↓ は 40 未満の数の後ならどこでも変化の量ですが、`BPM 90↑` は 90 と読みます）。スペースで区切ったスタイルの列では、スペースの後の語は次のタグとみなし、前の数をテンポとして読みます（`バラード BPM 70 遅くて切ない`・`BPM 90 落ちサビ` は 70・90）。ただし `BPM 50 上げて` のように動詞の形（上げて・上げる・上げます・上げよう・上げろ など）が続くときと、`BPM 50 くらい上げて`・`BPM 50 程度アップ` のようにスペースの後に「くらい・ほど・程度・前後・近く・ばかり」などを挟んで増減の語が続くときは変化の量です（`BPM 70 前後 ダウン系` も読みません）。「を・が・も」の後ではスペースは区切りになりません。読点（、）や「！」の後は、`BPMを40程度、上げて`・`BPMを20、上げます` のように動詞の形が続くときだけ変化の量で、`BPMが66、遅い` のようにそのほかの語が続くときは次のタグとみなして 66 と読みます。かっこで囲んだ数は、「を・が・も」の後で増減の語が続くとき（`BPMを（20）上げて`）と、スペースで区切った列で 100 未満の数の後に動詞の形や「くらい・程度」などを挟んだ増減の語が続くとき（`BPM（50）上げて`・`BPM（50）くらい上げて`）に変化の量です（`BPM（80）ダウン系`・`BPM（50）アップ` は 80・50）。
     - 迷う書き方は読まずに残します。読み取れなかったテンポは、譜面を指定して送るときにスタイルにもう 1 つテンポが書き足されることがあるので、`NN BPM` の形で書くのが確実です。
   - 「チップの内容で作り直す」は、チップが 1 つ以上選ばれているときに表示され、選択中のチップからプロンプト全体を作り直します（手で編集した部分は置き換わります。音声は生成しません）。
3. **譜面の計画**: Full / Melody / Off のボタンから選びます（説明はボタンのツールチップと下の行に表示されます）。Full はメロディ＋コードの譜面を先に計画し（編集可能）、Melody はメロディのみを計画、Off は譜面なしで直接生成します（最速）。
   - Off モードの cfg_scale は ComfyUI のテンプレートと同じ 1.0 です。公式 YuE2 ランタイムの off モードと同じ誘導にしたい場合は「詳細パラメータ」の「公式 off 互換 (1.01)」を押します（AR が 2 分岐になり約 2 倍遅くなります）。
   - 「レンダリングステップ」の公式値は 32 です。減らすと速くなりますが音質が下がります（32 未満では注意が表示されます）。
4. **譜面を指定して生成**: 「下の ABC 譜面を固定して音声だけを生成する」を ON にすると、入力した ABC 譜面をそのまま使います。送信時に次を自動で確認します。
   - コードのない譜面を Full で送ろうとした場合は Melody に切り替えます。コード付きの譜面を Melody で送ろうとした場合は「コードを削除して Melody で生成」か「Full モードに切り替えて生成」を選べます。小節の長さが拍子と合わない小節（弱起など）がある譜面では、コードを削除するとそれより後の小節線が拍子どおりの位置に書き直されることを、確認とお知らせで示します（5 章）。
   - 公式の記法チェック（YuE2 公式 abc_tools の検査を移植したもの）に通らない場合や、譜面と歌詞のセクション数が合わない場合は内容を表示して確認します。「非ネイティブ記法のまま送信」でそのまま生成もできます。一度「送信」を選んだ指摘は、同じ譜面・同じ歌唱テキストで送り直すときには再確認しません（新しい指摘があれば確認します）。ピアノロールの「この譜面で再生成」でも同じ確認を行います。
   - 歌詞にセクションタグ（`[Verse]` など）が一つもない場合は、確認ダイアログではなく送信後の通知で「タグを付けると対応が取りやすくなる」と案内します（公式: 歌詞はセクションタグ付きで書く）。
   - スタイルのテンポが譜面の `Q:` と違う場合は、スタイル側を譜面のテンポに合わせます（公式: テンポは譜面とスタイルで揃える）。スタイルのテンポは上の書き方のどれでもその位置で `NN BPM` に書き換え、テンポがなければ末尾に `, NN BPM` を加えます（`Q:1/4=8` のような極端なテンポでも、送信のたびに追記されることはありません）。`Q:"Allegro" 1/4=140` や `Q:C=140` のような `Q:` も読み取ります。
   - 譜面に `Q:` がない場合はスタイルを変えません（記法チェックが `Q:` の欠落を指摘します）。ただし「コードを削除して Melody で生成」を選んだときは、スタイルにテンポがあればそれを `Q:` として譜面に書き込みます（このときは欠落の指摘は出ません。スタイルにもテンポがなければ `Q:` は補わず、記法チェックが指摘します）。
   - 確認でキャンセルした場合、モードや譜面（コードの削除）、スタイルのテンポは変更されずに残ります。
   - ピアノロールでの編集は、この欄に自動では入りません。使うときは「ピアノロールの譜面（編集済み）を読み込む」を押します（編集がなければ「選択中の曲の譜面を読み込む」）。
   - ピアノロールの「この譜面で再生成」で送信できたときは、その譜面をこの欄に写します（欄が空か、その曲の譜面や直前に再生成した譜面が入っているときだけ。別の譜面があるときは写さず、「「譜面を指定して生成」の ABC 欄には別の譜面があるため、再生成した譜面はコピーしていません」とお知らせします）。確認でキャンセルしたときや送信に失敗したときは、欄を変えません。
5. **曲長の上限**: 自動（既定）では、設定の「曲長の既定上限」（既定 360 秒 = 公式ノード・テンプレートの値）を下限に、長い歌詞（推定 × 1.3 + 15 秒）や固定した譜面（譜面の長さ × 1.15 + 10 秒）のときは延長します。25 トークン = 1 秒で、モデルが自然に終われば上限より短くなるので、普通の長さの曲が長くなることはありません（上限が大きいほど VRAM の予約は少し増えます）。プロンプト（スタイル・歌詞・譜面）が長いと、モデルの文脈長（約 24576 トークン）に収めるため ComfyUI が実際の上限を自動で短縮します（長い譜面や大きな上限ほど短縮されやすく、短縮されたときはライブラリに表示されます）。生成中の進行状況では、音楽段は「生成済み 約 N 秒（T トークン・上限 M 秒・曲の終わりで自動停止）」と表示します（上限は天井なので、バーは割合ではなく動作中の表示です）。「（譜面の長さから延長）」「（歌詞の長さから延長）」は、実際に既定上限より延ばしたときだけ表示します。
   - 上限が固定した譜面より短くなる場合は、送信前に「曲長の上限が譜面の長さより短くなっています」と確認します（「M:SS のまま生成」かキャンセル。手動の上限では「上限を M:SS に広げて生成」も選べます）。自動でも、設定の「曲長の最大値」が譜面より短いときは確認します。AI 編集の「この譜面で再生成」とカバーでも同じ確認を行います。
   - 手動の上限は、スライダーを動かすか曲の設定を再利用するまでは、設定画面の既定上限に従います。
6. **生成する**: 初回は ComfyUI の起動（10〜40 秒）とモデル読み込みがあります。RTX 5090 では 1 分の曲に約 25〜30 秒かかります。
   - 「生成する」の後は、新しい曲と続くバリエーションが完成するたびに表示を切り替えます（「最近の生成」で曲を手で選ぶまで）。ピアノロールに未保存の編集（まだ反映していない ABC テキストを含む）がある間は切り替えず、「最近の生成から開けます」とお知らせします。ピアノロールにまだ反映していない ABC テキストがあるときは、「生成する」を押しても選択を変えません（テキストが消えないように。新しい曲は「最近の生成」から開けます）。
   - 「バリエーション数」を空にして確定すると、直前の数に戻ります。
   - 待機中・生成中の曲を選ぶと、プレイヤーには「生成が完了すると再生できます」と表示されます（エラーやキャンセル済みの曲は「音源がありません」）。
   - 日本語でひらがな版があるときは「生成にはひらがな版の歌詞を使用します。」と表示されます（右の欄が空のときは表示されません）。
7. 生成後、プレイヤーで再生し、「譜面（ピアノロール）」で編集できます。曲長の上限まで生成された（途中で切れた可能性がある）曲には「上限到達」と表示されます。
8. **選択中の曲の設定を再利用**: スタイル・歌詞（ひらがな版を含む）・曲タイトル・モード・シード・詳細パラメータ・曲長の上限（手動に切り替わります）を復元します。譜面を固定して作った曲は同じ譜面を固定し、譜面を計画して作った曲は同じシードで計画し直します。バリエーション数は 1 に戻ります。

**曲名**: 曲名は 1 行・60 文字までです。
- 作曲の「生成する」は「曲タイトル」欄の名前、作曲の「インストゥルメンタル版を生成」はその名前に「（インスト）」を付けた名前になります。
- ピアノロールの「この譜面で再生成」は選択中の曲の今の曲名（ライブラリで変えた名前を含む）、ピアノロールの「インストゥルメンタル版を生成」は「<曲名>（インスト）」、ライブラリの「上限を N 秒に広げて再生成」と AI 編集の再生成は今の曲名のままです（AI 編集では、曲を読み込まずに入力した内容の最初の再生成と、編集で歌のある曲が歌なしに、または歌なしの曲が歌のある曲に変わったときは、下の「曲タイトル欄が空のとき」の行のとおり自動で付けます）。
- すでに「（インスト）」付きや「インスト: …」の名前には印を付けません。長い名前は印が収まるよう短くします。
- 曲タイトル欄が空のとき、カバー、上の場合の AI 編集の再生成では自動で付けます: 歌詞の最初の行（タグの行を除く。24 文字まで）、歌なしのインストゥルメンタルでは「インスト: <スタイルの主な語>」、どちらもなければスタイルの先頭（24 文字まで）か日時です。
- 生成中にライブラリで曲名を変えても、変えた名前が保たれます。

### 4.1 日本語歌詞のひらがな化（生成用）

歌詞の言語で「日本語」を選ぶと「ひらがな化（生成用）」ボタンが出ます。押すと漢字を読み（ひらがな）に変換した「ひらがな版」が右側に表示され、生成にはこちらが使われます。ひらがな化は公式の手順ではなく、日本語の歌い方を安定させるための本アプリ独自の工夫です（YuE2 は漢字・かなのどちらも受け付けます）。

- 左が元の歌詞（漢字あり）、右がひらがな版です。右側は自由に編集できます（読みの誤りを直す、区切りを変えるなど）。右側が空のときは、生成には左の歌詞（漢字あり）を使います。
- 「変換内容の確認」を開くと、元の歌詞の漢字の部分だけに読みが表示されます（送り仮名は含みません。例: 照らして → 照(て)らして）。読みは右のひらがな版から取るので、右側で読みを直すと確認表示もそれに合わせて更新されます（入力が止まってから約 0.5 秒後）。右の行と対応が取れない行は辞書の読みを橙色で表示します。辞書で読めない漢字（燦・𠮟 など）は警告され、確認表示では波線が付きます。確認表示を作れないときはエラーの行が出ます。
- 変換中はボタンが「変換中…」になり、横の「キャンセル」で取り消せます（右の欄は変換前のままです。初回の辞書の読み込み中も使えます）。変換中（と「ひらがな版を破棄」の前の確認中）は、作曲・カバー・AI 編集の生成のボタンは押せません。
- 変換はボタンを押したときだけ行われます。ひらがな化の後に左の歌詞を変えると「ひらがな化の後に左の歌詞が変更されています（生成時にどうするか確認します。「再度ひらがな化」を押すと、変更のない行の読みは残ります）」と表示されます。
  - 「再度ひらがな化」を押すと、左の歌詞が変わっていない行は右の欄で手直しした読みを残し、新しい行や変えた行だけを変換します（行を足したり消したりしても対応を取ります。残した行の数はお知らせで表示します）。右の欄の行の数を手で変えていた場合は、手直しを行ごとに残せないため、置き換える前に確認します。すべて変換し直すには「ひらがな版を破棄」してから「ひらがな化」を押します。
  - そのまま生成すると「再度ひらがな化して生成」「漢字の歌詞で生成（ひらがな版を破棄）」「今のひらがな版で生成」「キャンセル」を選ぶ確認が出ます。ここでの「再度ひらがな化して生成」も上のボタンと同じく、変わっていない行の手直しした読みを残し、変えた行だけを変換し直します（右の欄の行の数がひらがな化したときと変わっている場合は全体を変換し直し、確認でもそう表示します）。漢字の誤字直しなど読みが変わらない修正なら「今のひらがな版で生成」で手直しを残せます。ひらがな化に失敗したときは、漢字の歌詞か今のひらがな版で生成するかを選べます（ライブラリから読み込んだ曲や「再利用」した曲でも同じです）。右側で読みを直しただけでは確認は出ません。
- 曲に保存される歌詞、書き出し時のタグ、同期歌詞の埋め込みには左の歌詞（漢字あり）が使われます。ひらがな版は `lyrics_sung.txt` として曲フォルダに残ります。
- 「ひらがな版を破棄」を押すと、左の歌詞のまま生成します。右の欄に手直しがあるときは確認します（手直しの確認のため、初回は辞書の読み込みで少しの間「確認中…」と表示されます。その間に曲の選択や AI の案などで歌詞が入れ替わった場合は、何も破棄せずにその旨を表示します）。
- 譜面があるとき（譜面を固定した作曲、カバー、AI 編集）は、歌詞欄の下の「セクションごとの音数とモーラ数（参考）」で、譜面の各セクションのボーカルの音数と、ひらがな版のモーラ数（ゃゅょ などの小書きは数えず、っ・ー・ん は数える）を比べられます。日本語の歌詞に混ざった英単語（全角の英字を含む）は推定した音節数で数えます。英語の歌詞では単語ごとの母音のまとまりから推定した音節数（語末の黙字の e は数えない。±1 程度ずれることがあります）、中国語では漢字の数を表示します。0.6 倍未満や 1.3 倍を超えるセクションは橙色になります。歌詞が空のときは歌詞の入力を促します。

### 4.2 インストゥルメンタル版（歌なし）を作る

- **新規に作る**: 「インストゥルメンタル版を生成」を押します。まず譜面だけを計画し、ボーカル声部の音符を伴奏声部に移してから、歌なしで生成します（YuE2 公式スキルの手順）。譜面の計画中は「キャンセル」で止められます（「譜面の計画をキャンセルしました」とお知らせします）。
  - 歌詞を入力していればその歌詞で、空なら公式と同じ `[Intro] [Verse] [Chorus] [Outro]` の骨組みとインストゥルメンタル用スタイルで譜面を計画します。計画と生成には同じシードを使います。モードが Full / Melody で「譜面を指定して生成」が ON のときは、計画せずに ABC 欄の譜面を変換します。
  - 譜面の計画中は、セクションタグの設定・詳細パラメータ・曲長の上限は変えられません（理由はツールチップに表示）。曲タイトルは計画中も編集でき、計画が終わった時点の内容を使います。計画中に書き換えたスタイルはこの曲には使わず、計画を始めたときのスタイルで生成します（その旨をお知らせします。書き換えたスタイルはフォームに残ります）。計画中に設定画面で変えた曲長の設定は使われます。
  - スタイルは公式の手順どおり、ボーカルや言語の語を除いて先頭に `Instrumental,` を付け、末尾に `no vocals, no singing, no choir, no spoken words` を加えたものになります。テンポは譜面の `Q:`（`Q:"Allegro" 1/4=140` などの書き方を含む）に合わせます。
  - 「セクションタグ（[Verse] など）だけを歌詞として渡す（公式既定）」が ON のときは、譜面のセクション名から作った `[Verse]` などのタグだけを歌詞として渡します。OFF にすると空の歌詞で生成します。
  - フォームの ABC 譜面（ボーカル入り）は書き換えられません。
- **既存の曲のインストゥルメンタル版**: ピアノロールの「インストゥルメンタル版を生成」を押すと、表示中の譜面から同じ手順で生成します（スタイル・シード・詳細パラメータは選択中の曲のもの）。
- 小節の長さが拍子と合わない小節がある譜面では、変換でそれより後の小節線が拍子どおりの位置に書き直されます（音の時間位置は変わりません。お知らせに小節の位置を表示します）。
- 曲フォルダには、変換後の譜面（`score.abc`）に加えて、変換前の譜面（計画した YuE2 の譜面、または表示中のボーカル譜。`score_source.abc`）が保存されます。`song.json` には移した音符の数（`instrumental_transfer`）と、計画したときはその入力（スタイル・歌詞・モード・シード。`params.plan`）が記録されます（公式スキル: 計画と元の譜面を残す）。
- インストゥルメンタルの曲の「歌詞」には、実際にモデルへ渡したセクションタグ（`[Intro]` `[Verse]` …）が保存されます。書き出し時のタグや曲名の自動付与では、タグの行は使われません。
- スタイルのチップに「インストゥルメンタル」はありません（スタイルの語だけでは歌詞や譜面のボーカルが残るため）。
- YuE2 の性質上、まれに声が混じることがあります。その場合はシードを変えるか、「ボーカル分離」で伴奏だけを取り出してください。

## 5. ピアノロールで譜面を編集する

- **ボーカル / 伴奏声部** の 2 声部を切り替えて編集します。クリックで音符追加、ドラッグで移動、右端ドラッグで長さ変更、右クリックまたは Alt+クリックで削除、Ctrl+ドラッグで範囲選択。
  - 長さを変える右端の範囲は音符の幅に合わせて狭くなります。とても短い音符はドラッグで移動になるので、Ctrl+ホイールで拡大してから長さを変えてください。
  - 右クリックでの削除は音符の表示領域だけで働きます（上部のコード・小節番号の行や鍵盤の列では削除しません）。
  - キーボード操作（Space で試聴 / 停止、Delete で削除、↑↓ で半音・Shift+↑↓ でオクターブ、←→ でスナップ単位の移動、Ctrl+Z で元に戻す、Ctrl+A ですべて選択）は、譜面エディタにフォーカスがあるとき（ピアノロールを一度クリックした後）に働きます。ボタンにフォーカスがあるときの Space はそのボタンを押します。音符をドラッグしている間（マウスボタンを押している間）は Delete・矢印キー・Ctrl+Z は効かないので、ボタンを離してから操作してください。
  - 1 回のドラッグ（移動・長さ変更・追加）は「元に戻す」1 回分です。ドラッグの結果が元と同じ（長さを変えて戻した、動かして戻したなど）なら編集にはならず、元に戻す手順も増えません。読み込んだ譜面まで元に戻すと「編集済み」が消え、元の譜面のテキストがそのまま使われます。
- 上部にコード記号とセクション名（intro / verse / chorus…）が表示されます。コードの編集は「ABC テキスト」タブで行えます（例: `"Am7"` のように引用符で書きます）。
- テンポの欄は 20〜300 の整数に丸め、Enter か欄を離れたときに確定します（Esc で取り消し。スピンボタンの矢印はすぐに反映）。
- 調の欄は YuE2 のネイティブ記法で使える 30 の調から選びます（調号だけが変わり、音の高さは変わりません）。全体の ±1 移調は調とコード記号も一緒に動かします（±8va と選択範囲の移調は音符だけ）。音域（MIDI 0〜127）を超える移調はできません。
- 編集しても末尾の空小節は残ります。消したいときは「末尾の空小節を削除」を押します。
- 「ABC テキスト」タブで変更して「テキストを譜面に反映」を押していない間は、タブに「未反映」と表示されます。その状態でエディタ内のほかの操作をすると「テキストを譜面に反映する」か「変更を破棄して続ける」を選ぶ確認が出ます（反映した場合は、もう一度その操作をしてください。カバーと AI 編集の画面側のボタンでの確認は 6 章・8 章）。タブを切り替えるときは「反映して切り替える」「変更を破棄して切り替える」「キャンセル」を選べます。
- 「テキストを譜面に反映」の後に、公式の記法チェック（参考）と、歌詞とのセクションの対応についての注意が表示されます（次の編集で消えます）。
- **拍子と合わない小節**: 小節の長さが拍子と合わない小節（弱起、拍の不足など）がある譜面では、読み込んだときに「小節の長さが拍子と合わない小節があります（ボーカル 2 小節目・… ほか N か所）。…」と表示します。ピアノロールは拍子どおりの小節線で表示し、編集・「テキストを譜面に反映」・「ABC を読み込む」で書き戻すと、それより後の小節線を拍子どおりの位置に書き直します（音の時間位置は変わりません。その旨を表示します）。曲末の短い小節と、拍子が変わる直前の小節は対象外です。
- 曲中の転調や拍子変更（SheetSage2 の転写に含まれることがあります）はそのまま保持され、編集後の書き出しでは公式の転写と同じ形で書き戻されます（`V: Vocal` / `V: Ins` の直後の `M:` / `K:` 行で新しいグループを始め、小節の途中の転調は両声部に `[K:…]` を書きます）。調の欄は曲頭の調だけを変え、曲中の転調は残ります。全体の ±1 移調では転調先の調も一緒に動きます。
- 「譜面を試聴」で簡易シンセによる確認ができます。「五線譜」タブで楽譜表示に切り替えられます。
- 「この譜面で再生成」を押すと、編集した譜面を固定して音声だけを生成し直します（コードがあれば Full、なければ Melody モード）。作曲画面では、譜面を表示している曲（選択中の曲）のスタイル・歌詞・シード・詳細パラメータで 1 曲だけ生成します（公式の編集手順と同じく、変えるのは譜面だけです）。フォームの内容（スタイル・歌詞、ひらがな版を空にしたなどで歌われる歌詞が違う場合を含む）と違う場合はその旨が表示されます。Off モードで cfg 1.01（「公式 off 互換」）を使って作った曲では、「この譜面で再生成」と「インストゥルメンタル版を生成」は AI 編集と同じく公式既定の 1.0 を使います。
- **作曲画面での編集の保持**: ピアノロールの編集は曲ごとに残ります。生成が終わって選択が変わっても失われず、その曲を選び直すと編集が表示されます。ほかの曲の編集はピアノロールの下に一覧され、「この曲を開く」「ABC 欄に読み込む」を選べます。「編集を破棄」を押すと（確認のあと）曲の譜面に戻ります。
- 「ABC を読み込む」「ABC を書き出す」「MIDI を読み込む」「MIDI を書き出す」で入出力できます。読み込めるのは 8MB までの `.mid` / `.midi` / `.abc` / `.txt` です。書き出しは `.mid`（`.midi` と入力すればそのまま）/ `.abc` のファイルだけを作ります（それ以外の拡張子を入力すると `.mid` / `.abc` を付け、お知らせに実際のファイル名を表示します）。読み込みや書き出しの失敗は、どのタブでもエディタ下部の行に表示されます。ファイルを選んでいる間に別の譜面が読み込まれた場合（作曲で次の曲が完了して選択が移った、カバーで転写が終わったなど）は、「読み込み中に別の譜面が読み込まれたため、ファイルの読み込みを中止しました」と表示して読み込みません。
- **MIDI の読み込み**: トラック名で声部を決めます。Vocal / Voice を含む名前（Vocal Melody など）は Vocal、Ins / Accompaniment / Piano / Guitar を含む名前（Ins Melody、Lead Guitar など）は Ins、Melody / Lead だけの名前は Vocal です。名前で決まらないトラック（Bass・Strings・Synth など）は、音符のある先頭 2 トラックを Vocal・Ins の順に使います。Piano や Guitar のように楽器名だけのトラックが 1 つしかない場合はメロディとして Vocal に入ります（Ins / Inst. / Instrumental / Accompaniment と名付けた単独トラックは Ins のまま。「Inst 1」のような番号付きの既定名は楽器名と同じ扱い）。
  - ドラム（チャンネル 10）のトラックは読み込みません（警告を表示します。ドラムにしか音符がないファイルは読み込めません）。
  - 音はスナップ単位に量子化されます。テンポが途中で変わるファイルでも拍の位置は保たれます。テンポは先頭（tick 0）のテンポ指定（複数あるときは最後のもの）を使い、ない場合は 120 BPM（MIDI の既定）です。不正なテンポ（0 や 1000 BPM 超など）は 120 BPM にして警告します。途中のテンポ変更は反映せず、警告で知らせます。
  - MIDI の拍子変更と調号は、譜面の拍子変更・転調として取り込みます（位置はスナップ単位に合わせます。tick 0 に複数あるときは最後のもの。長調・短調以外の調は同じ調号の長調・短調になります）。扱えない拍子（0/4 など）は警告して無視します。MIDI の書き出しには拍子の変更と調号（曲頭の調と転調）も含まれます。
  - 時間単位がタイムコード（SMPTE 形式）の MIDI と、10000 小節を超える長さのファイルは読み込めません。
- 譜面の解釈は公式の規則に合わせて厳密になっています。解釈できない譜面は「ABC テキスト」タブで直せます。
  - 異なる高さの音をタイでつなぐ、タイの後に休符を置くなどはエラーです。
  - `K:` は必須で、ヘッダーの最後（`V: Vocal` / `V: Ins` の声部の宣言の後、本文の前）に置きます。`L:` も必須で（ないと「L: 行がありません（…）」）、`1/<2 のべき乗、1024 まで>` で書き、行末に `%` のコメントを付けられます。
  - `M:` は `n/d`（分子 1〜64、分母は 2 のべき乗で 1024 まで）か `C` / `C|` です。`M:2+3/8`・`M:4/24`・`M:1/4096` などはエラーです。
  - 長さ 0 の指定（`C0`・`C/0`・`Z0`）と、10000 小節（4/4 換算）を超える長さはエラーです（`Z` の小節数や音の長さの数字の打ち間違いを想定しています）。
  - 本文中の `L:` / `Q:` / `w:` などのフィールド行はエラーになり、その行名を表示します。
  - 音符の行の全角スペースやノーブレークスペースは半角スペースと同じに扱います。ゼロ幅スペースなどの目に見えない文字は「解釈できない文字 U+200B（目に見えない文字です。削除してください）」のように文字コードで表示します。
  - 同じ位置に異なる 2 つのコード記号があるとエラーです（同じコードの重複は 1 つにまとめます）。
  - セクション名（`%` の行）は、その後に続く声部の小節に付きます（ボーカルを全部書いてから伴奏声部を書く書き方でも正しい位置になります）。最後の音符より後にある `%` の行（末尾の `% end` など）は無視し、空の小節は追加しません。

## 6. カバー / 耳コピ

1. 参考音源（WAV / FLAC / MP3 など）を選ぶか、「ライブラリの選択中の曲を使う」でライブラリの曲を使います（生成中や音声のない曲を選んでいる場合はその旨を表示します）。
2. 「メロディのみ」か「メロディ＋コード」を選んで「音源を譜面に転写」を押します（SheetSage2。1 分の曲で数秒）。転写が終わると、スタイルのテンポを譜面のテンポに合わせます。転写中は「キャンセル」で止められます。
   - 転写した譜面を編集したあとで転写し直すときは、編集が失われることを確認します。転写中に譜面を編集した場合も、転写結果で置き換える前に確認します（置き換えなければ、転写結果は反映しません）。
   - ライブラリで参考音源の曲を削除すると、参考音源は未選択に戻ります（転写した譜面は残ります）。
   - 転写中は、参考音源の選択・「抽出する内容」の切り替え・カバーの生成（ピアノロールの「インストゥルメンタル版を生成」を含む）は押せません。転写の記録には、転写を始めたときの「抽出する内容」が残ります。
3. 転写された譜面をピアノロールで整え、新しい歌詞とスタイル（既定は日本語のスタイル）を入力して「この譜面でカバーを生成」。元の音色や歌手の声は引き継がれません。「生成結果」には、この画面で最後に生成したカバーを表示します（ライブラリで別の曲を選んでも変わりません。生成中は「生成が完了すると再生できます」）。
   - 歌詞が空のときは「譜面のセクションから歌詞の枠を作る」で、譜面のセクション（intro / verse / chorus…）に合わせた `[Verse]` などのタグを並べられます（公式: セクションタグと歌詞の順序を譜面に合わせる）。元の歌詞と近い音数にすると歌いやすくなります。
   - 生成時には作曲画面と同じく、記法チェック・セクションの照合・テンポの同期・ひらがな版の確認を行います。曲長の上限は既定値（360 秒）を下限に、長い参考音源では譜面の長さ × 1.1 + 15 秒まで延ばします（設定の「曲長の最大値」が譜面より短いときは確認します）。
   - 「転写された譜面」の「ABC テキスト」に未反映の変更があるときに「この譜面でカバーを生成」「インストゥルメンタル版カバーを生成」を押すと、反映済みの譜面（ピアノロールと五線譜の譜面）で生成するかを確認します（「反映済みの譜面で生成」かキャンセル）。テキストの内容で生成するには、キャンセルして「テキストを譜面に反映」を押してから、もう一度生成してください。
4. **インストゥルメンタル版カバー（歌なし）**: 「インストゥルメンタル版カバーを生成」（またはピアノロールの「インストゥルメンタル版を生成」）で、転写したボーカルの音符を伴奏声部に移し、歌なしで生成します（公式のインストゥルメンタル版カバーの手順）。コードは「メロディ＋コード」で転写したときだけ使います（転写した後に「抽出する内容」を切り替えても、判定は転写したときの設定に従います）。歌う歌詞（ひらがな版があるときはひらがな版）が空のまま「この譜面でカバーを生成」を押した場合も、「インストゥルメンタル版カバー（歌なし）を生成」にするか確認します（ひらがな版についての確認があるときは、その後に、そこで選んだ歌詞で判断します）。

## 7. ボーカル分離

音源を選び、モデル（既定 BS-Roformer 1297）で「ボーカルと伴奏に分離」を押すと、ボーカル（`vocals.wav`）と伴奏（インストゥルメンタル。`instrumental.wav`）が保存されます。ライブラリの曲は曲フォルダの `separated`、ほかのファイルは楽曲保存先の `separated\<日時>_<ファイル名>` に入ります。VRAM 使用量は約 3〜4GB です。

- 分離結果は 32bit float の WAV で、劣化なく保存します。
- 入力はモノラル・ステレオ・5.1ch の音源に対応します。5.1ch は自動でステレオにダウンミックスします（センターとサラウンドは −3 dB、LFE は使いません）。それ以外の多チャンネルの音源は「ボーカル分離はモノラル・ステレオ・5.1ch の音源に対応しています（…）。ステレオに変換したファイルを選択してください。」となります。
- 5 種類の分離モデルすべてが使えます。htdemucs_ft の伴奏はベース・ドラム・その他の合計です（0 dBFS を超える音源でも楽器のバランスは崩れません）。同じ ComfyUI の起動中に何度でも分離できます。
- 各モデルは初めて使うときにダウンロードします（インターネット接続が必要です）。取得中のファイルは `<ファイル名>.mcs_part` に書いてから本来の名前にするので、通信の切断・キャンセル・終了で壊れたモデルが残ることはありません（次回は最初から取得し直します）。取得に失敗したときは原因に応じて、インターネット接続の確認、ディスクの空き容量と `models\separation` への書き込み権限の確認、時間をおいての再実行か別の分離モデルの選択を案内します。
- 分離モデルを読み込めないとき（ファイルの破損など）は、削除するファイルを示したエラーになります。そのファイルを削除してから実行し直すと取得し直します。VRAM が足りないときは「…VRAM が足りません。LLM を停止するなどして VRAM を空けてから、もう一度実行してください。」と表示します。
- 分離や整列が終わるとモデルは VRAM から解放されます（次の分離ではディスクから数秒で読み直します）。
- 分離の前は、結果のプレイヤーに「分離すると表示されます」と表示されます。「ライブラリの選択中の曲を使う」はカバー画面と同じく、生成中や音声のない曲にはその旨を表示します。
- 分離中は「キャンセル」で止められます（「出力を保存中」の段階を除く。分離の途中や初回のモデルの取得中でも数秒で止まり、取得途中のファイルは破棄します）。分離中は音源と分離モデルを変えられません。
- ライブラリの曲を分離し直すと、曲フォルダの 2 つのステムをまとめて置き換えます。どちらかを別のアプリ（プレイヤーなど）で開いていると保存に失敗し（「他のアプリで開かれている可能性があります」）、2 つとも元のファイルが残ります（新しいボーカルと古い伴奏が混ざることはありません）。
- ライブラリで音源の曲を削除すると、この画面の音源と分離結果も外れます（曲フォルダを楽曲保存先の外に残した場合は、音源のファイルだけ残ります）。分離中に削除した場合は分離を中止し、エラーではなく「曲がライブラリから削除されたため、分離を中止しました」とお知らせします（分離結果は保存せず、削除した曲フォルダが作り直されることはありません）。
- 書き出しのタイミング自動検出が分離したステムは別の場所に保存され、この画面の分離結果を上書きしません（9 章）。

## 8. AI 編集

- ライブラリで曲を選び、「AI 編集」で自然文の指示を送ります（例: 「サビのコードをジャズ風にリハーモナイズして。メロディは変えないで」「テンポを 8 上げてロック調に」「歌詞の 2 番を書き直して」）。
- 既定ではローカルの llama.cpp（Qwen3-14B）が送信時に自動起動します（自動起動の間は「考え中…」、「LLM を起動」で起動したときはボタンに「LLM を起動中…（最大 3 分）」と表示し、どちらも 180 秒で打ち切ります）。思考モード（既定 ON）では 1 回 20〜30 秒かかりますが、編集の正確さが大きく向上します。
  - 思考の長さは既定で自動的に制限します（譜面の編集は約 4,000 トークン、歌詞の作成は約 1,000 トークンで思考を切り上げ、回答を書かせます）。Qwen3 は音節を数え直したり小節を確かめ直したりして思考が止まらないことがあり、制限がないと応答の長さ上限（8,192 トークン）を思考だけで使い切って「LLM の応答が長さ上限で途切れました」になります。設定の「思考の長さを自動で制限する」をオフにすると思考を打ち切らなくなり、精度が上がることがある代わりに、この失敗が起こることがあります。歌詞の作成では、思考を打ち切った後も回答が長さ上限（思考 1,000＋回答 3,072 トークン）に達したとき（スタイルの語を繰り返し続けるなど）、思考なし・temperature 0.7 以上・同じ語を避ける設定で自動的にもう一度作成します（作曲画面にその旨を表示。譜面の編集はやり直しません）。
  - このアプリが起動していない llama-server が LLM ポートで動いている場合は「外部の llama-server（ポート N・このアプリでは停止できません）」と表示され、起動・停止のボタンは出ません。
  - LLM の設定を変えて再起動を待っている間は「LLM の設定が変更されています。次の AI リクエストで新しい設定で再起動します。」と表示されます。
  - ローカル LLM の状態は「稼働中」「起動中」（プロセスは動いているがまだ応答しない）「稼働中（変更前の設定）」（ポートの変更前の設定で動いている）「停止」です。「起動中」「稼働中（変更前の設定）」の間も「LLM を停止（VRAM 解放）」で止められます。ほかの画面（作曲の「歌詞とスタイルを作成」など）の AI への依頼が応答を待っている間は止めず、「LLM を停止できませんでした: AI の応答を待っている依頼があります。完了するかキャンセルしてから停止してください」と表示します。
  - ローカル LLM で長い譜面（目安として思考モードで 7〜10 分以上。音符の多い譜面ほど短い曲から）を送る前は、AI が返す譜面が応答の上限やコンテキスト長に収まらないおそれがあるため「譜面が長いため失敗する可能性があります」と確認します（「このまま送る」かキャンセル）。スタイルや歌詞だけを変える指示ならそのまま送れます。譜面を変えるときは、設定で「思考モード」をオフにする、「コンテキスト長」を増やす、クラウドの API に切り替える、のいずれかを試してください。同じ譜面で「このまま送る」を選んだ後は確認しません。
  - AI が依頼を拒否したときは「LLM が応答を拒否しました（…）。指示の内容を変えてもう一度お試しください」と表示します（同じ指示で送り直しても結果は変わりません）。
- 返ってきた提案は「差分を表示」で確認し、「適用」→「この譜面で再生成」で音声を生成します。
  - AI の応答を待っている間は、「この譜面で再生成」「選択中の曲を読み込む」「LLM を停止（VRAM 解放）」/「LLM を起動」「会話をリセット」「送信」、提案チップ、「メロディを保つよう再依頼」は押せません（「キャンセル」で依頼を取り消せます）。「適用」は押せます。
  - 依頼した後に譜面・スタイル・歌詞を編集してから（応答待ちの間に別の返答を適用した場合も）「適用」を押すと、「依頼した後に編集された内容があります」と確認します（「置き換える」かキャンセル）。「差分を表示」は依頼したときの内容との比較で、その後に編集があれば注意書きを表示します。
  - 「適用」がひらがな版を作り直している間に、別の曲が読み込まれたり、譜面・スタイル・歌詞・ABC テキストが変わったりした場合は、提案を適用せずにお知らせします（もう一度「適用」を押してください）。作り直しの間は「会話をリセット」も押せません（「提案の適用（ひらがな版の作り直し）が終わるまでお待ちください」）。
  - 「この譜面で再生成」の確認と送信の間は、「適用」「選択中の曲を読み込む」と歌詞欄の「ひらがな化」「ひらがな版を破棄」は押せません（「生成の送信中です。確認が終わるまでお待ちください」）。テンポを譜面に合わせるときは、スタイル欄のテンポだけを書き換えます。
  - **未反映の ABC テキスト**: エディタの「ABC テキスト」に未反映の変更があるときに「この譜面で再生成」や「送信」を押すと、「未反映の ABC テキスト」の確認が出ます（「反映せずに続ける」かキャンセル）。続けると反映済みの譜面を使い（反映済みの譜面がなければ、譜面を計画し直すか、Off の曲は譜面なしで生成し、AI には譜面なしで送ります）、テキストはそのまま残ります。譜面を変える提案を「適用」するとき（テンポの確認で「譜面の Q: を N BPM に変更」を選んだときを含む）は「変更を破棄して適用」かキャンセルを選びます。この画面の確認には「テキストを譜面に反映する」の選択肢はないので、テキストを使うときはキャンセルしてエディタの「テキストを譜面に反映」を押してください。
  - 譜面の一部しか返ってこない場合、解釈できない場合、公式の記法チェックに通らない場合は、自動で 1 回だけ直した譜面を再依頼します。それでも問題が残るときは、適用時に内容を示して確認します。抜粋の判定では「短くして」「消して」「省略」「1コーラス」「remove」「trim」などの短くする指示も考慮し、指示どおりに小節の 30〜70% が残った返答には、差分を確認するよう注意を表示します（この場合も記法チェックは行い、通らなければ再依頼と適用時の確認を行います）。
  - 自動の再依頼は、送った譜面そのものに同じ問題がない場合だけ行います（元の譜面が非ネイティブ記法や解釈できない譜面なら、指摘を表示するだけです）。再依頼の返答に譜面がなかったときは最初の返答を残します（送った譜面をそのまま返した場合は、それを再依頼への答えとして扱い、次の「変更なし」の扱いになります）。
  - 返答の譜面・スタイル・歌詞が送った内容と同じ場合は「変更なし」として扱います（スタイルと歌詞は改行の種類と前後の空白、譜面は改行の種類と最後の改行 1 つの違いを無視して比べます）。何も変わらない返答には「⚠ AI が返した（項目）は送った内容と同じで、変更はありませんでした。指示を言い換えてもう一度お試しください。」と表示します。適用した提案に「メロディを保つよう再依頼」をしたときは、エディタには変更後の譜面があり、送るのは元の譜面なので、元の譜面に戻す返答は送った譜面と同じでも変更として扱います（適用していない提案では、エディタの譜面が元の譜面のままなので「変更なし」になります）。
  - 「メロディは変えないで」のような指示でボーカルの音符が変わった場合は、変わった小節を表示し、「メロディを保つよう再依頼」を 1 回だけ押せます。このボタンは最新の返答でだけ、その返答の後に譜面が変わっていない間に使えます（ほかのときは押せず、理由をツールチップに表示します）。再依頼の返答も同じようにボーカルの音符を比べ、まだ変わっていれば表示します。
  - ローカル LLM では、コンテキスト長に収めるため、古い返答は譜面を省いて送り、それでも収まらないときは古いやり取りから送らなくなります（返答に件数を表示します）。自動の再依頼が収まらない場合は行いません。設定のコンテキスト長が 0（モデルの設定値）のときは長さが分からないため、何も省略しません。会話がコンテキスト長を超えたと表示されたときは、設定の「コンテキスト長」を増やしてください。
  - 日本語でひらがな版がある曲では、歌われる読み（ひらがな版）も参考として AI に渡します。AI が歌詞を書き換えた提案を適用すると、変わった行だけひらがな版を作り直し、変わっていない行は手直しした読みを残します（「変更のない N 行は手直しした読みを残しました」）。右の欄の行の構成を手で変えていた場合は、全体を作り直します。右の欄を空にしているとき（漢字の歌詞で生成する扱い）は作り直さず、空のままです。
  - スタイルのテンポと譜面の `Q:` は揃えます。返されたスタイルのテンポが譜面の `Q:` と違う場合（スタイルだけが変わった提案も、スタイルのテンポだけ変えて `Q:` を直し忘れた提案も）は、譜面の `Q:` を変えるか、スタイルを譜面に合わせるかを確認します。提案で `Q:` だけが変わっていた（スタイルのテンポは送ったときのまま）場合は、「スタイルを譜面に合わせる」が先頭（Enter で選ばれる側）になり、依頼したテンポ変更が取り消されないようにしています。
  - 記法チェックに通らない提案を「適用」で受け入れた場合、その同じ指摘は最初の「この譜面で再生成」で再確認しません。
  - 「メロディを保つよう再依頼」や提案チップを押しても、入力欄に書きかけの指示は消えません。
  - 返答を待つ間は「考え中…」の横の「キャンセル」で依頼を取り消せます（その指示は対話から消え、入力欄から送った指示は、入力欄が空なら入力欄に戻ります）。
  - 「「メロディは変えない」指示」の判定は、曲全体のメロディについての指示だけを対象にします（「Aメロのメロディは変えないで」「サビの旋律はそのまま」のようにセクションを指定した指示は対象外です）。
- **再生成**: ボタンの名前は譜面の有無で変わります。譜面があるときは「この譜面で再生成（Full / Melody）」で、譜面にコードがあれば Full、なければ Melody（作曲のピアノロールと同じ）です。譜面のない曲では、Off で作った曲は「再生成（譜面なし・Off）」（新しい譜面を計画する生成にはなりません）、それ以外は「再生成（譜面を再計画・Melody / Full）」で、曲のシードで譜面を計画し直します。開始すると「再生成を開始しました」とお知らせします。
  - 対話している曲（「編集中の曲」の欄で再生できる曲）のシード・詳細パラメータ・モードを使います。ライブラリの選択が変わったり解除されたりしても同じです。曲長の上限は既定値・元の曲の上限・編集後の歌詞や譜面の長さのうち最も長いものです。曲名は対話している曲の今の曲名（ライブラリで変えた名前を含む）のままです（曲を読み込まずに入力した内容の最初の再生成と、編集で歌の有無が変わったときは自動で付きます。4 章の「曲名」）。
  - 再生成しても対話とフォームの内容は残り、続けて指示できます。譜面を計画した場合は、生成が終わるとその譜面を空のエディタに読み込みます（「ABC テキスト」に未反映の変更があるときは読み込まず、ライブラリの曲の「ABC 譜面」で確認できることをお知らせします）。
  - AI 編集で譜面が付いた Off の曲は譜面固定で生成し、Off 用の cfg 1.01（「公式 off 互換」）は公式既定の 1.0 に戻します。
- 譜面は保存・編集されたテキストのまま送ります（末尾の改行も含めて。YuE2 は譜面をそのままトークン化します）。
- **選択中の曲との関係**: この画面は、表示している間だけライブラリの選択に従います。別の画面にいる間にほかの曲が選ばれた場合は、戻ったときに読み込みます。ただし作業中の内容（対話、応答待ちの AI への依頼、変更した譜面・スタイル・歌詞、未反映の ABC テキスト、曲を選ばずに入力・貼り付けした内容、ライブラリで削除された曲での作業）があるときは「作業中の内容があります」と確認し、「選択中の曲を読み込む」（作業中の内容は失われ、応答待ちの依頼は取り消されます）か「今の作業を続ける」を選べます。確認は新しく選ばれた曲ごとに 1 回です（同じ曲を選び直しても、間にほかの曲を選ばなければ再度は聞きません）。続ける場合、ライブラリの選択はそのままで、画面には「ライブラリで選択中の「…」はこの画面に読み込んでいません」と「選択中の曲を読み込む」ボタンが表示されます。
- 設定で Anthropic API や OpenAI 互換 API に切り替えられます（キーは `secrets.json` に保存）。生成前にローカル LLM を止めて VRAM を解放する設定が既定で有効です（11 章）。

## 9. 書き出しと同期歌詞

1. 形式（MP3 / M4A / FLAC / OGG / Opus / WAV 16bit・24bit・32bit float（無劣化））、ビットレート、ラウドネス正規化（-14 LUFS など）、フェード、無音トリム、メタデータ、ジャケット画像を設定します。
   - サンプルレートは元の音源のまま書き出します（ラウドネス正規化をしても同じ。OGG でも正規化できます）。ただし OGG Vorbis は元が 40〜50 kHz 以外（96 kHz や 22.05 kHz など）のとき、MP3 は 32 kHz 未満のときに 48 kHz に変換し、「… で書き出すため、サンプルレートを … Hz から 48000 Hz に変換しました」と表示します。Opus は常に 48 kHz になります。
   - ビットレートは、MP3 では規格の値（64・80・96・112・128・160・192・224・256・320 kbps）から、M4A・OGG・Opus では 64〜320 kbps を 16 kbps 刻みで選びます（ほかの形式で選んだ値は、MP3 では最も近い規格の値（中間なら高い方）で書き出します）。OGG はチャンネルあたり 240 kbps、Opus は 256 kbps が上限で、モノラルの音源などで上限を超える値は上限まで下げます。3 チャンネル以上の音源の OGG は、必要な最低値（5.1ch は 84 kbps、ほかはチャンネルあたり 32 kbps）まで上げます。どちらの場合も、実際の値を書き出しの後に表示します。それでもエンコーダーが受け付けないときは「この音源のチャンネル数・サンプルレートでは、選んだビットレートで書き出せません。ビットレートを変えるか、別の形式を選んでください」と表示します。
   - 無音トリムは同期歌詞の時刻もずらし、フェードアウトはトリム後の長さに付きます（新しい末尾より後の行は警告付きで除かれます）。曲の長さを読み取れないときは、フェードアウトを付けずに警告します。
   - 正規化を使わないときは「0 dBFS を超えるサンプルをクリップする」を選べます。生成時のピークが 0 dBFS 以上の曲では正規化を勧める注意が出ます。
   - 書き出しには元のファイルの音声だけを使います（元のファイルのジャケット画像・タグ・チャプターは引き継ぎません）。タグには画面で入力した値だけを書き、空欄の項目は書きません。読み込めないジャケット画像は警告になり、画像なしで書き出します。
2. **音源**: ライブラリで選択中の曲が自動で入ります（「音声ファイルを選択」でほかのファイルも使えます。タイミングの自動検出中と書き出し中は音源を変えられません）。ライブラリで読み込み済みの曲の名前を変えると、タイトル欄（書き換えていなければ）と保存するファイル名の既定値も新しい名前になります。この画面は表示している間だけ選択に従い、作業中の内容（検出・打刻・入力した時刻、編集した歌詞やタイトル、実行中のタイミング自動検出）があるときは AI 編集と同じく「作業中の内容があります」と確認します。選択中の曲が生成中のときは「完了すると読み込みます（作業中の内容がある場合は確認します）」と表示されます。
   - 「音声ファイルを選択」で別のファイルを選ぶと、ライブラリの選択は外れます。検出・打刻・入力した時刻があるときは「同期歌詞のタイミングがあります」と確認し（「切り替える」かキャンセル）、切り替えると行の時刻はすべて仮の時刻に戻ります（歌詞とタイトルはそのまま）。まだ音源がないときに選んだ最初のファイルでは、入力済みの時刻をそのまま使います（確認しません）。
   - 今の音源と同じファイルを選び直すと、長さと打刻用のプレイヤーを読み直し、「同じ音声ファイルを読み込み直しました（行の時刻はそのままです）」と表示します（行の時刻・歌詞・タイトルはそのままです。ほかのアプリで書き換えたファイルに備えて、画面に残っている前回の分離結果は使いません）。
   - 「書き出す」を押してから（確認と保存先の選択を含めて）書き出しが終わるまでは、ライブラリの選択に従いません。書き出しに成功して結果を表示しているときは、その間に選んだ曲や完了した曲を読み込まず、「選択中の曲を読み込む」で読み込みます。書き出しに失敗したときや、書き出しの後に完了した曲は、これまでどおり選択に従います。
3. **同期歌詞**: 「タイミングを自動検出（分離＋整列）」を押すとボーカル分離→歌詞の整列が走り、行ごとの時刻が入ります。実行中は「キャンセル」で止められます（分離の段階でキャンセルすると整列は始まりません。このボタンは自動検出の間だけ出ます）。再生しながら「打刻」で手動修正、時刻の直接編集も可能です。
   - 自動検出は、フォームに読み込んでいる曲（ライブラリの選択ではなく）の音声を分離し、その曲のひらがな版で整列します（歌詞欄と行の数が同じときだけ。違うときは歌詞欄の歌詞で整列します）。自動検出中にライブラリでその曲を削除すると、エラーではなく「曲がライブラリから削除されたため、タイミングの自動検出を中止しました」とお知らせして中止します（分離結果は保存しません）。
   - **分離結果の再利用**: 同じ音源の前回の分離結果を使います。ライブラリの曲では、曲フォルダの分離結果を次の順に使います: まず自動検出が作った `<曲フォルダ>\separated\align\vocals.wav`（初回の自動検出や「ボーカルを分離し直す」をオンにしたときに作られます）、次にボーカル分離の画面の `<曲フォルダ>\separated\vocals.wav`（モデルは問いません）。曲と同じ長さ（±0.5 秒）のファイルだけを使い、使ったファイルはお知らせに表示します。このときボタンは「タイミングを自動検出（曲フォルダの分離結果で整列）」または「（前回の分離結果で整列）」になります。
   - 「ボーカルを分離し直す」をオンにすると分離し直します（音源を変えるとオフに戻ります）。自動検出のための分離は、ライブラリの曲では `<曲フォルダ>\separated\align`、ほかのファイルでは `<データルート>\cache\align_stems`（毎回同じフォルダ）に保存し、ボーカル分離の画面の結果は上書きしません。分離のモデルは、ボーカル分離の画面で選んだものではなく、いつも BS-Roformer 1297 です。自動検出が自分の分離結果を作った後でボーカル分離の画面で分離しても、自動検出は自分の分離結果を使い続けます。ボーカル分離の画面の結果を使わせるには、エクスプローラーで `<曲フォルダ>\separated\align` フォルダを削除してから自動検出してください（「ボーカルを分離し直す」は BS-Roformer 1297 で分離し直して `separated\align` を置き換えるだけで、ボーカル分離の画面の結果には切り替わりません）。
   - 実際には歌われていない行（曲長の上限で途中までしか生成されなかった曲の後半など）は、整列が音声の末尾に押し込んだ低い確からしさの結果になるため、検出した時刻としては使わず「音声中に見つかりませんでした（推定時刻・灰色）」として前後から推定します。音声が歌詞に比べてかなり短いときは、収まる先頭の行だけを整列し、残りは推定します（最初の行も収まらないときはエラーになります）。
   - 日本語は、助詞の「は」「へ」を発音どおり「わ」「え」に直してから整列します（「私は東京へ」→ わたしわとうきょうえ、「あなたは」→ あなたわ。漢字の歌詞で整列するときは、漢字も辞書の読みでひらがなにして送ります。ひらがな版で整列するときも、品詞は漢字の歌詞から判定するので「へいき」「はは」などは書かれたとおりに読みます）。対象は、漢字・カタカナ・英字、または辞書にある 2 文字以上のひらがなの語（あなた・きみ・ぼく・ここ・そら など。「僕ら」「私たち」の「ら」「たち」は前の語に含めます）の直後にある助詞です。1 文字の語や辞書にない語の直後、笑い声の「ははは」などは書かれたとおり「は」のまま送ります。日本語の行に混ざった英単語は 1 語ずつ整列します。絵文字・記号・顔文字の「ヽ」などは読み飛ばし、半角カタカナは全角に直して整列します。
   - 灰色の行は前後の行から推定した時刻です。仮の時刻（未設定の行）が残っている間は「同期歌詞を埋め込む / .lrc を出力」は既定で OFF になり、仮の時刻がそのまま書き出されることはありません。打刻や時刻の入力のあとに「歌詞から行を作り直す」を押しても、未設定の行は仮の時刻のまま残ります（自動検出で全行に時刻が入っているときだけ、編集した行を前後から推定します）。
   - 歌詞の言語は歌詞から自動で判定します（切り替え可）。整列できるのは英字（アクセント付きを含む）、日本語（かな・漢字。pykakasi）、中国語（漢字。pypinyin。読みは漢字の連なりの文脈で選びます）の歌詞です。韓国語・ロシア語・ギリシャ語・アラビア語・タイ語・ヒンディー語など、それ以外の文字体系（言語「その他」）は、任意コンポーネント「多言語ローマ字化（uroman）」を「設定 → セットアップをやり直す」から導入すると整列できます（MMS の整列モデルは uroman のローマ字表記で学習されています）。未導入のときは該当行を飛ばして前後から推定し、通知でその行数をお知らせします。英語の歌詞に混ざったキリル文字の単語なども同じ扱いです（ß・æ・ø・ł などの英字は未導入でもつづりに直して整列します）。
   - **時刻の直接編集**: Enter か欄を離れたときに確定し、Esc で取り消します。`分:秒.百分の一秒`（例 `01:23.45`）、秒数だけ、IME の全角数字を受け付けます。読み取れない入力は赤枠になります。実際に入力した時刻だけを使い、欄をクリックして離れただけでは「手入力」になりません。
   - キーボードでは、歌詞の行の文字にフォーカスして Enter / Space でその行を選びます（時刻の欄と ▶ は別の操作です）。
   - **歌詞を編集したとき**: 歌詞欄を編集して「歌詞から行を作り直す」を押していない間は、その旨が表示されます。同期歌詞をオンにして書き出すと、「行を作り直す（書き出しは中止）」か「このまま書き出す」を選ぶ確認が出ます。
4. 「書き出す」で保存先を選びます。MP3 には SYLT（同期）と USLT（全文）、M4A には ©lyr、FLAC / OGG / Opus には LYRICS と UNSYNCEDLYRICS（全文）、同期歌詞があれば SYNCEDLYRICS（LRC 形式）を埋め込みます（©lyr と LYRICS は、同期歌詞があれば LRC 形式、なければ全文）。同期歌詞を有効にすると、同名の `.lrc` も出力します。WAV にはタグ（ジャケット画像を含む）を付けませんが、同期歌詞を有効にすると `.lrc` は出力します。
   - 同名の `.lrc` がこのアプリで作ったものでないときは上書きせず、`<名前>.mcs.lrc` に保存してその旨を表示します（`<名前>.mcs.lrc` もこのアプリのものでなければ、`.lrc` は出力しません）。
   - 書き出しは保存先の隣の `<名前>.mcs-tmp.<8 文字の英数字>.<拡張子>`（`.lrc` も同様）に書いてから最後に置き換えるので、失敗しても以前のファイルは残ります。書き出し中にアプリが強制終了した場合はこのファイルが残ることがありますが、次に同じ名前へ書き出したときに自動で削除されます（同じ名前の `.lrc` の作業用ファイルと、以前の版の `<名前>.mcs-tmp.<拡張子>` も含みます。ほかのファイルには触れません。手動で削除してもかまいません）。
   - 同じ名前への書き出しが実行中のとき（画面を再読み込みする前に始めた書き出しなど）は、新しい書き出しは始まらず「同じ名前（…）への書き出しがまだ実行中です…。終わってから、もう一度書き出してください」と表示します。拡張子だけが違う名前（`曲.flac` と `曲.mp3`）や、拡張子の前に `.mcs` が付いただけの名前（`曲.flac` と `曲.mcs.mp3`。退避先の `曲.mcs.lrc` を共有します）も `.lrc` が同じになるため対象です。画面を再読み込みしても、前の画面で始めた書き出しは続いています。
   - 元の音源と同じファイルを保存先にすると、元のファイルには触れずに「書き出し先が元の音源と同じファイルです。別の名前か場所を指定してください」となります。
   - 同期歌詞なしで同じ名前に書き出し直すと、以前の書き出しでこのアプリが作った `.lrc`（と `<名前>.mcs.lrc`）は削除します。それ以外の `.lrc` は残し、その旨を表示します。

## 10. ライブラリ

- 新しい順に 500 曲まで表示し、それより古い曲は「さらに読み込む」で表示します。検索はタイトル・スタイル・歌詞（歌われた歌詞（ひらがな版）を含む）が対象で、大文字・小文字、全角・半角、カタカナ・ひらがなを区別しません。
- 曲名はダブルクリックか F2 で変更できます（Enter で確定、Esc で取り消し）。
- 曲の状態は 完了 / 生成中 / 待機中 / エラー / キャンセル済み で表示されます。待機中と生成中の曲には「キャンセル」があります。
- 「削除」は確認のあとで曲と曲フォルダを削除します（ごみ箱には移動しません）。生成中の曲は削除できないので、先にキャンセルしてください。待機中の曲は待ち行列から取り消してから削除します。曲フォルダを削除するのは、その曲のフォルダ（楽曲保存先の中、または保存先を変える前にアプリが作った `日付\時刻_ID` のフォルダ）だけで、それ以外の場所のフォルダは残して「曲フォルダは保存先の外にあるため残しました: …」と表示します。
  - 曲フォルダかその中のファイルがほかのアプリ（プレイヤー、そのフォルダを開いているターミナル、書き出し中の ffmpeg など）で使われているときは、何も削除せずに「曲フォルダかその中のファイルが使用中のため削除できませんでした（…）。閉じるか完了してから、もう一度削除してください」と表示します（曲もライブラリに残ります）。削除する権限がないときなども、何も削除せずに「…アクセスできないため削除できませんでした（…）」と表示します。
  - 曲フォルダのドライブ（外付けドライブや NAS）に接続できないときは、ライブラリの曲だけを削除し、「曲フォルダのドライブ（ネットワークの場所）に接続できないため、曲フォルダが残っているか確認できませんでした。接続後、残っていればエクスプローラーで削除してください: …」と表示します。
  - 曲フォルダを作る前に終わった曲（生成の開始前の失敗、待機中のキャンセルなど）と待機中の曲には曲フォルダがありません（曲フォルダは生成が始まってから作られます）。詳細に「フォルダ」の行と「開く」は出ず、削除の確認は「「<曲名>」をライブラリから削除します。元に戻せません。」になります（待機中の曲は「待機中の生成も取り消されます。」が続きます）。確認を開いている間に曲の状態が変わったときは、確認の文もそのときの状態に合わせて変わります。待機中の曲の生成が始まったときは「「<曲名>」の生成が始まったため、今は削除できません。先にキャンセルしてください。」になり、「削除する」は出ず「閉じる」だけになります（生成が終われば、また「削除する」が出ます）。生成中の曲は詳細に「フォルダ」の行が出て、フォルダができるまでは「開く」で一番近い上のフォルダが開きます。生成中にアプリを終了して中断した曲（「アプリ終了により中断」）は、曲フォルダができる前でも予定のフォルダが表示されることがあります（削除しても問題ありません）。
- 詳細の「開く」や、プレイヤー・書き出し・ボーカル分離の「フォルダを開く」「出力フォルダを開く」は、フォルダがなくなっていれば残っている一番近い上のフォルダを開きます。ドライブに接続できないときは「フォルダが見つかりません: …」と表示します。
- 曲長の上限まで生成された曲には「上限到達」と表示され、「上限を N 秒に広げて再生成」（前回の 1.5 倍、上限の最大値まで）で生成し直せます（曲名は今の曲名のまま。ほかの生成ボタンと同じく二度押しは無視します）。長いプロンプトのために ComfyUI が上限を短縮していた場合は、上限を広げても変わらないため、歌詞・スタイル・譜面を短くするよう案内します。
- 各曲の主な設定（モード・シード・曲長の上限・cfg・ステップ）と、実際に歌われた歌詞（ひらがな版）を確認できます。生成時間には、ComfyUI の待ち行列で待った時間は含みません。
- 曲フォルダの `song.json` には、打ち切りの有無（`truncated`）、実際に使われた上限（`effective_max_seconds`）、VAE FP32 の有無、ComfyUI とアプリのバージョン、使ったワークフローが記録されます。失敗・キャンセルした生成では `failure.json` が残ります。
- 生成が終わっても、書き出し・AI 編集・ボーカル分離の画面の曲は切り替わりません（お知らせが出ます）。

## 11. 設定

- **モデル精度**: BF16（標準）と INT8（省 VRAM。ComfyUI 公式テンプレートの既定。音響段・VAE も低精度のため音質がわずかに劣る可能性）。未導入の精度は「未導入」と表示され選べません。
- **VAE デコード方式**: 生成した潜在表現を音に戻す方法です。「自動」（既定）は、生成開始時の空き VRAM とモデル精度から、通常デコード（ComfyUI 公式テンプレートのノード）が収まる曲はそのまま、収まらない長い曲は分割デコード（公式ランタイムと同じ方式。収まる最大のタイルで）を使います。「通常」は常に公式テンプレートのノード（VRAM 不足のときは ComfyUI が分割に切り替えて再試行するため、その分だけ遅くなります）、「分割」は常に分割です。実測では分割と通常の音の差は −55 dB 以下で、継ぎ目の劣化はありません。分割は数秒〜十数秒遅くなります。使った方式は曲フォルダの `song.json`（`vae_decode`）に残ります。
- **VAE を FP32 で実行**: 公式ランタイムと同じく VAE を FP32 で動かします（既定 OFF。実測では FP16 との差は聴感上検出できず（−54 dB 以下）、復号が約 2 倍遅く VRAM も約 2 倍必要です）。変更すると、アプリが起動した ComfyUI が空いているときに自動で再起動します（生成や分離・整列などのツールの実行中なら、それが終わってから）。設定画面の ComfyUI 欄の「VAE 精度」に、動作中の ComfyUI の状態（FP32 / 既定（FP16）、アプリが起動していない ComfyUI では「不明」）が表示され、再起動を待っている間はその旨が表示されます。別のアプリや残ったプロセスが起動した ComfyUI が動いている間は反映されません（その ComfyUI を終了してから「起動」を押すか、ポートを変更してください）。
- **曲長の既定上限 / 最大値**: 最大値は 60〜900 秒、既定上限は 8 秒〜最大値の整数に、入力欄を離れたときと保存時に丸めます。
- **ComfyUI**: 状態・GPU・VRAM・VAE 精度・キュー（「実行中 N / 待機中 N」）などを表示します。動作確認済みのバージョン（v0.37.0）と違う ComfyUI が動いているときは注意が出ます。本アプリのノードが見つからないときは「ノードパックを修復」で入れ直せます（反映には ComfyUI の再起動が必要です）。
- **場所とポート**:
  - データルートと楽曲の保存先は、保存場所の手順と同じ条件で確認します（使えないパスは赤字で表示され、保存できません）。
  - 楽曲の保存先を変えると、それ以降に生成した曲が新しい場所に入ります。既存の曲は移動せず、ライブラリからは元の場所のまま再生・書き出し・削除できます。
  - ポートは 1〜65535 の整数で、ComfyUI と LLM には別の番号を指定します。
  - ComfyUI のポート・データルート・VAE 精度を変えて保存すると、このアプリが起動した ComfyUI は空き次第（生成やツールの実行中なら終わってから）新しい設定で再起動します。LLM ポートの変更は次の AI リクエストで反映されます。手で停止・起動し直す必要はありません。
  - 新しいデータルートに必要なコンポーネントがない場合、ComfyUI は新しい場所では起動できず、動作中の ComfyUI は空き次第停止します。設定画面の案内に従って、「セットアップをやり直す」で新しい場所にセットアップしてから ComfyUI を起動してください。
  - 以前の版にあった「生成時に ComfyUI を自動起動する」は削除しました（生成や分離などのツールは、必要なときに常に ComfyUI を自動で起動します）。
- **ComfyUI の起動・停止**: 「起動」は ComfyUI が応答するまで最大 4 分ほど「起動中…」と表示します（画面を離れて戻っても、起動中・稼働中は押せません）。停止中と、このアプリが起動していない ComfyUI では「停止」は押せません。「保存」と「LLM 設定を保存」は同時には実行できません。このアプリの生成やツールの実行中は「停止」を押せません（「生成・ツールの実行中は停止できません。先にキャンセルしてください。」と表示されます）。ComfyUI の待ち行列にほかのクライアントから送られた処理だけがあるときは、停止するとそれらが失敗することを確認します。このアプリが起動していない ComfyUI（前回の異常終了で残ったプロセスや別のアプリの ComfyUI）も停止できません。タスク マネージャーで終了するか、ポートを変更してください。起動を待っている間に「停止」を押した場合、起動側のエラーは表示しません。
  - 「VRAM を解放」は、応答する ComfyUI があるときだけ押せます（停止中は「ComfyUI は停止しています」、起動中は「ComfyUI の起動中です。起動が終わってから実行してください」とツールチップに表示）。解放できなかったときは「VRAM を解放できませんでした: ComfyUI が 10 秒以内に応答しませんでした」などと表示します。
- **AI 編集（LLM）**: ローカル LLM では「GPU に載せる層数」を変えられます。VRAM が 12GB 程度以下の GPU では、層数を減らすか小さいモデル（8B クラスの Q4 GGUF など）を使い、「曲の生成前に LLM を停止」を有効にしてください。
  - **コンテキスト長**: 8,192 / 16,384（既定）/ 24,576 / 32,768 トークンから選びます。AI 編集で会話がコンテキストを超えたと表示されたときに増やします（大きいほど VRAM を多く使います）。config.json に手で 0 を書いた場合は「0（モデルの設定値）」と表示され、モデルに記録された長さを使います。
  - **思考の長さを自動で制限する**（思考モードが ON のときだけ表示。既定 ON）: ローカル LLM の思考を、歌詞の作成では約 1,000 トークン、譜面の編集では約 4,000 トークンで切り上げて回答を書かせます（llama.cpp の思考予算。使い切ると「時間が限られているので、ここまでの思考で答える」という旨の文を添えて思考を終わらせます）。オフにすると思考を打ち切らないため精度が上がることがありますが、思考だけで応答の長さ上限（8,192 トークン）を使い切り「LLM の応答が長さ上限で途切れました」になることがあります。そのときはこの設定をオンに戻すか、思考モードをオフにしてください（エラーの文もまずそれを案内し、それでも途切れる場合はコンテキスト長を増やすかプロバイダを切り替えるよう案内します）。歌詞の作成の応答が上限で途切れたときは、思考なしで自動的にもう一度作成します（4 章の手順 0）。
  - プロバイダ・API のモデル・temperature・思考モード・「思考の長さを自動で制限する」は「LLM 設定を保存」の次の依頼から使われます。ローカル LLM の GGUF モデル・層数・コンテキスト長・ポートの変更は、次の AI リクエストでこのアプリの llama-server を再起動して反映します（それまでは「LLM の設定が変更されています。次の AI リクエストで新しい設定で再起動します。」と表示されます）。
  - ローカル LLM の状態は「稼働中」「起動中」「稼働中（変更前の設定）」「停止」で表示します（8 章。この画面では、開いたときと保存したときの状態です）。このアプリが起動していない llama-server が LLM ポートで動いている場合は「稼働中（このアプリが起動していない llama-server）」と表示されます。このアプリからは停止・再起動できず、ここでの設定も反映されません。
  - 「曲の生成前に LLM を停止して VRAM を解放する」（既定 ON）では、AI の応答を待っている途中なら生成は最大 3 分待ってから（進行状況「AI の応答を待っています」。キャンセル可）ローカル LLM を停止します。
  - 設定中の GGUF モデルが `models/llm` にないときは「（見つかりません）」と表示されます。一覧から選び直して保存してください。
  - ローカルの llama-server は、`%APPDATA%\MusicCreatorStudioYuE2\llama_api_key.txt` に保存した API キーを使って接続します（自動で作られ、起動時に環境変数で渡すので、ユーザー名が日本語のプロファイルでも起動できます）。
  - API キーは `secrets.json`（`%APPDATA%\MusicCreatorStudioYuE2`）に暗号化せずに保存されます。保存済みのキーは「キーを削除」で消せます（空白だけを入力して保存しても、保存済みのキーは消えません）。設定の保存に失敗したときは、OpenAI 互換 API のキーは Base URL と一緒に保存するため保存せずに入力欄に残します（設定を直してから、もう一度「LLM 設定を保存」を押してください。Anthropic のキーは保存されます）。temperature は Anthropic API には送信しません（スライダーはローカルと OpenAI 互換 API で使います）。api.openai.com の推論モデル（gpt-5・o シリーズ）にも temperature は送りません。
  - OpenAI 互換 API のキーは、最初に使った接続先（オリジン）にだけ送ります（「保存済みのキーは <接続先> にだけ送信されます。」）。キーは最初に送信した時点でその接続先に結び付き、応答の前にキャンセルしたりタイムアウトしたりしても結び付いたままです。接続先にまったく届かなかった場合（接続の拒否、名前の解決の失敗、約 21 秒の接続のタイムアウト。Base URL の打ち間違いなど）は結び付けません。Base URL を別の接続先に変えると、キーを入力し直すよう表示され、保存済みのキーはほかの接続先には送りません。キーを入力し直して保存すると、結び付けはやり直しになります。Base URL が別のコンピューターへの `http://` の場合は、キーが暗号化されずに送られるため注意が出ます。

## 12. トラブルシューティング

- **生成が始まらない / ComfyUI が起動しない**: 設定画面の「ログを開く」で `comfyui.log` を確認してください。ドライバが古い場合は更新が必要です（CUDA 13.0 は 580.88 以上）。
- **VRAM 不足**: 設定でモデル精度を INT8 にし、「生成後に VRAM を解放する」を有効にします。長い曲の復号は「VAE デコード方式」が自動で分割に切り替えます（VRAM の少ないカードでは「分割」に固定してもかまいません）。AI 編集や分離と同時に使う場合は LLM を停止してください。
- **日本語の歌が不自然**: 公式ベンチマーク（WildSongBench）は英語・中国語のみで、日本語は本アプリでは実験的扱いです。スタイルに `Japanese` を含める（公式ガイドでも言語はスタイルに書く）、複数のシードで生成して選ぶ、本アプリ独自の回避策として歌詞をひらがな化する、などを試してください。
- **処理が止まる・長く待たされる**: 生成は 60 分、ツール（転写・分離・整列・譜面の計画）は 30 分で打ち切ります。ComfyUI の待ち行列でほかの処理を待っている時間と、PC がスリープ・休止状態だった時間はこれに含みません。待ち時間が 3 時間を超えると「ComfyUI で他の処理の完了待ちが長すぎます」として諦めます。ComfyUI の画面や別のアプリから処理が取り消された場合は「ComfyUI の待ち行列からこの処理が削除されました」と表示されます。
- **「他のアプリで開かれている可能性があります」**: 曲やステムのファイルを置き換えるときに、そのファイルがほかのアプリ（プレイヤー、書き出し中の ffmpeg など）で開かれていると保存に失敗します。元のファイルはそのまま残ります。そのアプリを閉じてからやり直してください。
- **楽曲の保存先に書き込めない**: 生成を始めるとき（LLM の停止や ComfyUI の起動より前）に、楽曲の保存先へ書き込めるかを確かめます（保存先の中に一時フォルダ `.mcs_write_check_<ID>` を作って小さなファイルを書き、すぐに削除します）。外付けドライブを外しているなどで保存先を作れないときは「曲の保存先フォルダ … を作成できません（設定の「楽曲の保存先」のドライブやフォルダを確認してください）: …」、書き込めないときは「曲の保存先フォルダ … に書き込めません…」で生成は失敗します。アクセスが拒否されたときは、フォルダへの書き込み権限と、Windows セキュリティの「コントロールされたフォルダー アクセス」でこのアプリが許可されているかを確認するか、設定の「楽曲の保存先」を変更してください。既定の保存先は「ミュージック」の中にあり、この機能の保護対象なので、機能を有効にしている場合はアプリを許可するか、保存先を別のフォルダにしてください。
- **「データルート … にこのアカウントではアクセスできません」**: 別の Windows アカウントや、Windows を入れ直す前のアカウントでセットアップしたデータルートです（Windows のドライブ直下にセットアップが作ったデータルートは、作ったアカウントだけが使えます。2 章）。この説明は、Windows のドライブ直下にあって、このアカウントでは中を一覧できないフォルダ（Windows 自身のフォルダを除く）のときだけ出ます。セットアップの「保存場所」か設定画面で別のフォルダをデータルートにするか、このフォルダを使い続けるなら、管理者として実行したコマンドプロンプトまたは PowerShell（「ターミナル (管理者)」でもかまいません）で、メッセージの最後の行に示された `icacls "<データルート>" /grant "*<SID>:(OI)(CI)F"` を実行してからやり直してください（メッセージは選択してコピーできます。このアカウントにもフルコントロールを与えるため、両方のアカウントから使えるようになります）。フォルダ名に `$`・`` ` ``・`%`・`!`・全角の引用符が含まれるときは、コマンドを貼り付けると別の場所に効いてしまうためコマンドは示さず、管理者へのアクセス権の追加の依頼を案内します。管理者権限がない場合は、別のフォルダを指定してください。
- **「データルート … にアクセスできません。フォルダへの読み取り・書き込みの権限…」**: それ以外のデータルート（別のドライブ、入れ子のフォルダ、ネットワーク上のフォルダ、`C:\Program Files` のような書き込めないフォルダ、コントロールされたフォルダー アクセスで守られたフォルダ）に書き込めないときの表示です。フォルダの権限（ネットワーク上のフォルダでは共有のアクセス権も）と、Windows セキュリティの「コントロールされたフォルダー アクセス」でこのアプリが許可されているかを確認するか、別のフォルダをデータルートに指定してください。
- **プロキシ・証明書**: セットアップのダウンロードとクラウドの API（Anthropic API や PC の外の OpenAI 互換 API）は、https の接続先には環境変数 `HTTPS_PROXY`（または `ALL_PROXY`）、PC の外の `http://` の OpenAI 互換 API には `HTTP_PROXY`（または `ALL_PROXY`）のプロキシを使い（`NO_PROXY` に書いた接続先は除きます）、Windows の設定画面のプロキシや自動構成スクリプト（PAC）は使いません。LAN 内の別の PC の OpenAI 互換 API に `HTTP_PROXY` が設定された環境でつながらないときは、その接続先を `NO_PROXY` に書いてください。プロキシが必要なネットワークでは、環境変数 `HTTPS_PROXY` を設定してからアプリを起動し直してください。ComfyUI とローカルの llama-server（この PC 上の接続先）にはプロキシを使いません。
  - 接続できないときは「ダウンロードの接続に失敗しました（…）」や「LLM サーバーに接続できません（…）。プロキシ経由でしか接続できないネットワークでは、環境変数 HTTPS_PROXY を設定してからアプリを起動し直してください」と表示します（接続のタイムアウトを含みます）。「LLM の応答がタイムアウトしました」は、送信した後に 600 秒以内に応答がなかった場合です。
  - HTTPS では、組み込みのルート証明書に加えて Windows の証明書ストアのルート証明書も信頼するので、ウイルス対策ソフトの HTTPS スキャンや社内の TLS 検査があっても、その証明書が Windows に登録されていれば接続できます。「証明書を検証できません（ウイルス対策ソフトの HTTPS スキャンや社内プロキシを確認してください）」と表示されたときは、それらの設定を確認してください。
- **AI 編集や作曲の AI で「別の llama-server が動作しています」**: このアプリの API キーを受け付けない llama-server（401 エラー）が LLM ポートを使っています。そのプロセスを終了するか、設定で LLM ポートを変更してください。
- **「音声ファイルを ComfyUI の入力フォルダ（…）にコピーできませんでした」**: 転写・分離・タイミングの自動検出で、音源を ComfyUI に渡せなかったときの表示です。続く原因（ディスクの空き不足など）と、`<データルート>\comfy_input\mcs_uploads` を確認してください（このアプリが起動していない ComfyUI では、アップロードのエラーが先に表示されます）。
- **旧版のアプリと併用している場合**: 旧版は同じデータルート（`C:\MCSYuE2`）を使い、ComfyUI を起動するたびに自分のノードパックを上書きします。旧版から ComfyUI を起動すると、新しい版を起動し直すまで分離の繰り返しや打ち切り検出などが使えなくなります。
- **設定ファイルが壊れた場合**: 読み込めない `config.json` は `config.json.bad-<数字>` として残し、既定の設定で起動します（データルートと楽曲の保存先は、残っていればアンインストール用の記録から戻します）。読み込めない `secrets.json` は `secrets.json.bad-<数字>`（数字は時刻）に移すので、API キーを入力し直してください。どちらも `%APPDATA%\MusicCreatorStudioYuE2` にあり、次に壊れたときに上書きされることはありません。起動時に、そのことと退避したファイルの名前を × で閉じるまで残るお知らせで表示します。同じ内容の壊れた `config.json` は、起動するたびに退避し直すことはありません。
- **ライブラリが開けない場合**: 起動時に `library.db` を開けないと理由を示すメッセージが出ます。［はい］でそのファイル（と `-wal` / `-shm`）を `library.db.corrupt-<日時>` に退避して空のライブラリで起動し（曲フォルダはそのまま残ります）、［いいえ］で終了します。
- **ComfyUI や llama-server が残る場合**: このアプリが起動した ComfyUI・llama-server・セットアップ中のツール（7zr・pip）・書き出しの ffmpeg は、アプリが異常終了しても一緒に終了します。それでも残っている場合（以前の版で起動したものなど）は、タスク マネージャーで終了してください。
- **ログの場所**: `%APPDATA%\MusicCreatorStudioYuE2\logs`（`app.log`、`comfyui.log`、`llama-server.log`）。起動時に大きくなっていたログは 1 世代だけ `app.1.log`（5MB 超）・`comfyui.1.log`・`llama-server.1.log`（20MB 超）に移します。
- **不具合を報告するとき**: 設定画面の「診断バンドルを作成」を押すと、ログ（`app.log`・`app.1.log`・`comfyui.log`・`comfyui.1.log`・`llama-server.log`・`llama-server.1.log`）・設定（API キーは含みません）・GPU やドライバなどの環境情報・導入済みコンポーネント・ComfyUI の Python パッケージ一覧・直近の失敗ジョブのワークフローと記録（`failure.json`: パラメータ・プロンプト ID・失敗時のバージョン）を 1 つの zip（`mcs-diagnostics-<日時>.zip`）にまとめて楽曲保存先に出力します。この zip を Issue に添付してください。
  - 楽曲保存先を使えないとき（外付けドライブの取り外し中、ネットワークの場所がオフライン、ドライブがいっぱい、読み取り専用、コントロールされたフォルダー アクセスなど）は、ログフォルダ（`%APPDATA%\MusicCreatorStudioYuE2\logs`）に作成します。作成後のお知らせに保存した場所が表示され、エクスプローラーでその場所が開きます。
  - zip には、直近の失敗ジョブ（最大 3 件）の歌詞・スタイル・譜面（`lyrics.txt`・`song.json`・`workflow_api.json`・`score.abc`）と、Windows のユーザー名を含むフォルダのパスが入ります（曲フォルダを作る前に失敗したジョブは、エラーの内容だけです）。未公開の歌詞などを公開したくない場合は、添付する前に中身を確認して該当ファイルを削除するか、非公開の方法で送ってください。
  - GPU ドライバや WMI が応答しない場合でも作成できるよう、環境情報の取得は 1 項目あたり最大 15 秒（Python パッケージ一覧は 60 秒）で打ち切ります。
- **ストアアプリ（MSIX パッケージのアプリ）の中から起動した場合**: `%APPDATA%` が仮想化され、設定とライブラリが `AppData\Local\Packages\...\LocalCache\Roaming\MusicCreatorStudioYuE2` に保存されることがあります。通常はスタートメニューから起動してください。
- **一時ファイル**: カバーや分離に使う音源は `<データルート>\comfy_input\mcs_uploads` にコピーされ、6 時間を過ぎたものは削除されます（削除するのはアプリがコピーした名前のファイルだけで、以前に楽曲の保存先をこのフォルダにしていたときの書き出しなどは削除しません。生成やツールで ComfyUI を使うときに、待ち行列が空なら最大 1 時間に 1 回確認します。使用中のコピーは使うたびに更新時刻が新しくなるため消えません）。生成や分離の結果は、アプリが起動した ComfyUI の出力フォルダ（`<データルート>\comfy_output` の `mcs`・`mcs_sep`）から曲フォルダに取り込んだあと削除します。取り込めずに残ったファイルも、同じ確認のときに 24 時間を過ぎたものを削除します。削除するのは ComfyUI がこのアプリの生成と分離のために保存した名前（`<英数字8桁>_<番号>_.flac` など）のファイルだけで、以前に楽曲の保存先をこれらのフォルダにしていたときの書き出しや診断バンドルなど、ほかのファイルは削除しません。ボーカル分離の作業用フォルダ（`mcs_sep_*`）は `<データルート>\cache\sep_work` に作られ、終わると削除されます（残ったものも 12 時間後に削除され、アンインストール時は cache フォルダと一緒に削除されます）。
  - 分離結果を置き換えるときは、元のファイルを一時的に `<ファイル名>.<ID>.mcs-bak` に移し、保存が終わると削除します。アプリが異常終了したときに残ることがありますが、削除してかまいません（自分で作った `vocals.wav.bak` などには触れません）。
  - 楽曲の保存先の書き込みの確認に使う `.mcs_write_check_<ID>` フォルダは、ウイルス対策ソフトなどが一時的につかんでいると空のまま残ることがあります。削除してかまいません。

## 13. アンインストール

Windows の「アプリ」からアンインストールすると本体を削除し、ダウンロードしたツール・モデル（データルート）と生成した楽曲を削除するかどうかを順に確認します。

- どちらの確認も既定（Enter）は「いいえ」です。新しい版へ更新するためのアンインストール（新しいインストーラーの「インストールする前にアンインストールする」）では「いいえ」を選んでください。
- 「はい」でも、このアプリが作成したものだけを完全に削除します（ごみ箱には移動しません）。
  - データルート: `runtime` 内のアプリのツール（ComfyUI・ffmpeg・llama.cpp・7zr）、`cache` 内のアプリの作業フォルダとダウンロードしたアーカイブ、`comfy_input\mcs_uploads`・`comfy_output\mcs`・`comfy_output\mcs_sep` の直下にあるアプリのファイル（音源のコピーと取得途中の `.part`、ComfyUI が生成と分離のために保存した `<英数字8桁>_<番号>_.flac` などの出力。この 3 つのフォルダの曲フォルダ・書き出したファイル・診断バンドル・サブフォルダは残し、空になったフォルダだけを削除します）、`extra_model_paths.yaml` と、セットアップでダウンロードしたモデル（`models` 内の YuE2・SheetSage2・Qwen3-14B・分離モデル・整列モデル。分離モデルを初めて使うときにダウンロードしたファイルと、取得途中の `*.mcs_part` を含みます）。自分で置いたモデルや、ほかのツールが同じ名前のフォルダ（`cache` など）に置いたファイルは残します。
  - 楽曲フォルダ: アプリが作った曲フォルダ（`日付\時刻_ID`）・`separated` 内の日時付きの分離結果・診断バンドル。書き出したファイルなど、ほかのファイルは残します（ログフォルダに作られた診断バンドルは、下の「アプリケーションデータを削除する」でだけ削除されます）。
  - ジャンクションやシンボリックリンク（`mklink /J` などでほかのツールと共有したフォルダ）は、リンクだけを削除し、リンク先の中身は削除しません。`runtime`・`cache`・`comfy_input`・`comfy_output`・`models`（と `models` 内のフォルダ）、`comfy_input\mcs_uploads`・`comfy_output\mcs`・`mcs_sep` がリンクの場合は、リンク先にあるアプリのモデルなども残ります。リンクを削除できなかったときは、データルートの中は何も削除しません（その旨は表示されません）。
  - 楽曲の保存先が、データルートの中のアプリが管理するフォルダ（`comfy_output\mcs`・`runtime\ComfyUI_windows_portable\ComfyUI\output` など）の中にある場合は、曲が消えないように、ツールとモデルは削除せずにその旨を表示します（曲を別の場所へ移してから、不要なファイルを手動で削除してください）。以前に、ツールとともに丸ごと削除されるフォルダ（`runtime\ComfyUI_windows_portable` など）の中を楽曲の保存先にしていて今は別のフォルダにしている場合も、そのフォルダにまだ何か残っていれば（ライブラリの曲はそこに残っています）同じく削除しません（「以前の楽曲の保存先（…）が…」）。曲を移すか削除してそのフォルダを空にすれば、次のアンインストールでツールとモデルを削除できます（記録されるのは、この版以降で楽曲の保存先を変えたときです）。生成した楽曲を削除するかの確認は、そのあと別に行います。
  - 空になったフォルダは削除します。ドライブ直下・相対パス・ユーザーフォルダそのもの（ドキュメント・ミュージック・OneDrive、ほかのユーザーや Public のフォルダなど）が記録されている場合は、何も削除せずにその旨を表示します。8.3 形式の短い名前（`MCSDAT~1` など）で記録されたフォルダの長い名前を確かめられない場合も同じで、楽曲の保存先（または何か残っている以前の楽曲の保存先）がそうなら、データルートの中にあるか分からないため、ツールとモデルも削除しません。記録されたフォルダが見つからない場合（削除済み・外付けドライブの取り外し中など）は、確認せずに飛ばします（リンク先がなくなったリンクや、権限がなく中を見られないフォルダも同じです）。
- 設定・ライブラリ（曲の一覧と履歴）・API キー・ログのフォルダ（`%APPDATA%\MusicCreatorStudioYuE2`）は、確認画面の「アプリケーションデータを削除する」にチェックを入れたときだけ削除します（既定はチェックなし。更新時のアンインストールでもチェックしなければ残ります）。
- パッシブ（`/P`）・サイレント（`/S`）でのアンインストールでは、データルート・楽曲・設定フォルダはすべて残します。
- 設定を残したままツールとモデルを削除した場合、再インストール後の初回起動ではセットアップウィザードが開きます（ライセンスの同意は記録されたままです）。ただし、データルートのあるドライブ（またはデータルートの一つ上のフォルダ）が見つからないとき（外付けドライブの取り外し中など）は、削除と区別できないためメイン画面が開きます。
